> **Partly superseded.** Rows A-01 to A-39 in [decisions.md](decisions.md) replace the language (TypeScript, not Python), the store (immutable maps, not SQLite) and the logic format (JS snippets in `node:vm`, not an expression language). Where they conflict, decisions.md wins. Read [architecture.md](architecture.md) first.

**Backbone:** Plan A (engine-first) has the highest average critic score (A 7.5, B 7.25, C 6.75), so it is the base. On top of it I added B's agent machinery (repair controls, ingest, `query_seed`, plan contract), C's delivery shape (end-to-end slice by Day 2, cut lines, stress suite) and every red-team fix: origin-tagged diffs, a validity filter for mutants, task `setup`, `foreach` in references, inline fixtures for scenarios, per-entity RNG streams, and collections keyed by name.

## 1. TL;DR

- **The engine works like a strict compiler and judge.** Logic is declarative (state machines, guards, effects, timers), written as typed expressions that are statically checked against the data model. Every error carries a code, path, `file:line`, hint and `owner_stage`, and the error messages are snapshot-tested because they are the engine's interface to the model. Generated worlds contain no LLM-written Python at all.
- **Writes are all-or-nothing and runs are deterministic.** Each request is one SQLite transaction under a global lock, and a failed call changes no state and does not advance the clock. The virtual clock moves +1s per committed write. IDs come from per-entity counters, and each entity's seed has its own RNG stream. A canonical state hash is CI-tested to be identical on reset and on a double run.
- **Graders must show they discriminate under the engine's probes, and only the engine decides.** Score = Σ weight·check × Π gates. Each check must be false at seed. The collateral gate is a hard multiplier that defaults to "the whole world is unchanged except …", and it counts only changes the agent caused. Verify runs the reference (must score 1), noop (0), every prefix (<1), an overbroad mutant (0), a wrong-target mutant (<1), the first page only (<1), an alternative valid solution (1) and a determinism check. Mutants are generated by the engine and discarded if they are invalid. References use only public routes, plus `capture`, `foreach` and `paginate_all`.
- **WorldGen builds in six gated stages**, each one "write object, check, repair". Fingerprints detect oscillation, a patch that adds errors is reverted, a stall moves to a stronger model, upstream errors trigger a bounded `amend` of the earlier stage, and budgets are capped in USD and wall-clock time. A run that can't pass ends in `<out>.FAILED/` with `FAILURE.md` and a non-zero exit. `update` changes a world in place and keeps existing rows byte-identical.
- **Delivery follows C's schedule.** A thin end-to-end slice by end of Day 2, an engine freeze at end of Day 3, ingest on Day 5, `update` on Day 6, a 15-prompt stress suite run twice (including vague and impossible prompts), and a timed live-run rehearsal on Day 8.

## 2. Key design decisions

| Decision | Choice | Why | Alternative rejected |
|---|---|---|---|
| Language/runtime | Python 3.12, `uv` | Pydantic, Faker, SQLite and the Anthropic SDK; fastest to build solo | TS/Node: weaker data tooling |
| World files | YAML directory split by stage; **every collection is a map keyed by name** (entities, fields, routes, workflows, actions, tasks) | Repairs target stable keys, fingerprints don't shift, diffs are readable | Lists plus RFC 6902 index patches (fragile, and fingerprints shift) |
| Validation | Pydantic v2 is the source of truth. JSON Schema goes into prompts as reference. **Expressions are stored as strings**, and the tool schema stays shallow | Avoids structured-output schema limits; the engine is the validator, not the decoder | Deep recursive strict tool schemas |
| Store | SQLite `:memory:`, one connection per world session; reset through the backup API | Real transactions, FK/UNIQUE/CHECK backstop, millisecond reset | Python dicts plus a hand-rolled undo |
| Constraint layers | A Python enforce layer produces precise errors; SQLite constraints are the backstop | Model-fixable messages, and corruption is impossible | DB constraints only (vague errors) |
| Custom logic | **Declarative only for generated worlds**: state machines, actions (input → guards → effects), timers, typed expressions, a rich builtin set | Static checkability is what makes repair converge; an AST lint is not a sandbox | Python handlers (C), or a `py:` hatch for generated worlds (A/B) |
| Escape hatch | No `py:` hatch in v1. COULD: allowed for hand-built worlds only, in a subprocess with rlimits and no network, behind a `ctx` proxy | Red-team showed AST scanning plus settrace can be escaped and is slow | AST-scanned in-process Python |
| Expression language | Python-expression subset (`ast.parse(mode="eval")` with a node whitelist), statically type-checked; `lookup()` returns Optional and must be used with `??` or `exists` | Models write it fluently; nulls are caught at check time | simpleeval/CEL evaluated only at runtime (B) |
| Clock | Starts at `clock.start`. +1s per committed write; reads and failed calls don't advance it. Jumps only through the admin API or task `setup`. Timers fire in chronological order | Deterministic, with strictly ordered timestamps | Wall clock; a clock that advances on every call |
| Timer vs. gate interaction | Every row change in the journal is tagged with its **origin** (`agent:<seq>`, `cascade:<seq>`, `timer:<name>`). Gates look only at agent- and cascade-originated changes. A **timer-horizon lint** flags seed rows whose timer would fire during the run window | Background timers can't zero a correct reference | Gates over the raw diff (A's bug) |
| Admin surface | **Separate port** (or in-process only). It serves state, diff, log, reset, clock, grade and hash | The agent can't inspect, reset or time-travel | `/_engine` prefix on the same port |
| Agent-facing docs | The engine generates `/openapi.json` for every world on the public port | Agents need to discover the routes; it also drives the conformance diff | Treating docs as a bonus (C) |
| Seed | The LLM writes a **generator spec, not rows**. v1 uses state-conditional generators plus **per-state invariants** plus **history derived automatically** from the state machine path. Simulation through real actions is SHOULD | Consistent by construction without building a research-grade simulator | Full simulation as the v1 path (A); free generator.py (C) |
| Seed RNG | `hashlib.sha256(rng_seed ‖ entity ‖ field)` stream per entity and field. `seed.lock.jsonl` is canonical and `update` never regenerates existing rows | Old tasks survive change requests | One shared RNG (C); RNG keyed by world hash (B) |
| Realistic text | A cheap model produces domain **value pools** once (`pools.yaml`, cached in the world); sampling is seeded | Faker alone gives lorem-style subjects | Faker only |
| Money | Integer minor units; canonical JSON uses sorted keys and RFC 3339 UTC | Closes determinism leaks | Floats |
| Grader shape | Σ w·check × Π gates. Each check is false at seed (after setup). Selectors are **relative to the seed, plus named anchors** | Sharp, and robust under `update` | Additive collateral weight (C's bug gives noop 0.4); hardcoded IDs (A) |
| Collateral default | `unchanged_except` over **the whole world** unless a task declares `collateral: allowed` with a reason | Covers entities added later | Hand-listed entity gates |
| References | A declarative call list with `capture` (JSONPath), `foreach`, `paginate_all` and `expect`. **Public routes only.** Every written ID comes from a capture or an instruction literal. Clock moves go only in `setup` | Bulk and paging tasks become expressible, and tasks are solvable by a real agent | Static call lists; clock moves inside references (B) |
| Mutants and decoys | Generated by the engine only, with a validity filter. **No decoys written by the LLM** | Model-written decoys are self-grading in disguise | B's decoys |
| Logic tests | Scenarios carry inline `given:` fixture rows, validated under full constraints | Decouples stage 3 from stage 4 | Defaults-only fixtures (B); undefined (A/C) |
| Repair edits | Keyed object replacement (`replace: workflows.ticket_lifecycle.actions.escalate`) plus search/replace inside large string fields; whole file for files under 150 lines | Stable targets | RFC 6902 patches |
| Verify execution | In-process ASGI app through `httpx.ASGITransport`, backup-API reset between runs, tasks verified in parallel across processes | Fast, with no port flakiness during repair | A uvicorn port per mutant |
| Interactivity | Non-interactive by default; `open_questions` get default answers recorded in the plan. `--interactive` and `--pause-after-plan` are optional | The live run is probably unattended, and this still means no silent guessing | Always asking a human |
| Temperature | Provider default (needed for extended thinking). Determinism comes from the engine and the lock files | Temperature 0 conflicts with extended thinking | Temperature 0 everywhere |
| Read and answer tasks | Out of scope for v1 and written into DESIGN.md. COULD: `POST /task/answer`, graded by expression | The spec grades end state | Inventing an answer channel early |
| Auth | Static bearer token. An `X-Actor` header selects a seeded user only when the workflow needs roles (e.g. approvals) | Faithful where it matters, with no RBAC scope creep | A full RBAC simulator |

entities:

      name: { type: string, required: true, max: 120, searchable: true }

workflows:
  ticket_lifecycle:
    entity: Ticket
    state_field: status
    initial: new
    history: { entity: TicketEvent, parent: ticket_id, kind_field: kind }   # used by seed history derivation
    states:
      new:       { invariant: "assignee_id == null and escalation_level == 0" }
      open:      { invariant: "assignee_id != null" }
      escalated: { invariant: "escalation_level >= 1 and assignee_id != null" }
      resolved:  { invariant: "resolved_at != null", terminal: true }
    on_create:
      effects:
        - set:
            sla_due_at: >
              now() + minutes(lookup(SlaPolicy, tier == self.customer.tier
                and priority == self.priority).response_minutes ?? 480)
        - emit: created
    actions:
      escalate:
        from: [new, open, escalated]
        to: escalated
        input: { reason: { type: string, required: true, max: 500 } }
        guards:
          max_level:
            expr: "self.escalation_level < 2"
            error: { status: 409, code: max_escalation, message: "Ticket already at level 2" }
          oncall_exists:
            expr: "exists(OnCallShift, level == self.escalation_level + 1 and starts_at <= now() and ends_at > now())"
            error: { status: 409, code: no_oncall, message: "No on-call agent for next level" }
        effects:
          - set:
              escalation_level: "self.escalation_level + 1"
              assignee_id: >
                lookup(OnCallShift, level == self.escalation_level + 1
                  and starts_at <= now() and ends_at > now()).agent_id
          - emit: { kind: escalated, note: "input.reason" }
      resolve:
        from: [open, escalated]
        to: resolved
        effects: [ { set: { resolved_at: "now()" } }, { emit: resolved } ]
    timers:
      sla_breach:
        when: "self.status in ['new','open'] and not self.sla_breached and now() >= self.sla_due_at"
        effects: [ { set: { sla_breached: true } }, { emit: sla_breach } ]
    scenarios:
      escalate_happy:
        given:
          Customer:    [ { id: CUS-0001, name: "X", tier: enterprise } ]

            expect: 200
            assert: "get(Ticket,'TCK-01001').escalation_level == 1"

        steps: [ { call: POST /tickets/TCK-01001/escalate, body: { reason: r }, expect: 409, expect_unchanged: true } ]

        given: { ... }

## 5. Engine: components and how each guarantee is implemented

**Components:**
- loader: merges files and keeps a YAML line map
- checker: layered passes
- expr: parse, type-check, eval
- store
- runtime: CRUD, list, workflow, timers, clock, transactions, origin journal
- seed materializer
- grade: grader, reference runner, mutants, verify
- servers: public, admin
- CLI

### Check

Passes run in layers. The checker stops at the first failing layer and reports every error within that layer, capped at 25 and deduplicated:

| L | Pass | Example codes |
|---|---|---|
| 0 | YAML parse | `YAML_SYNTAX` (line/col) |
| 1 | Pydantic schema | `SCHEMA_MISSING_FIELD`, `SCHEMA_BAD_TYPE` |
| 2 | Name resolution | `UNKNOWN_ENTITY`, `UNKNOWN_FIELD`, `UNKNOWN_ACTION`, `ROUTE_ENTITY_MISSING` (did-you-mean) |
| 3 | Expression type-check | `UNKNOWN_ENUM_VALUE`, `TYPE_MISMATCH`, `OPTIONAL_UNHANDLED` (bare `lookup().x`), `GUARD_NOT_BOOL` |
| 4 | Workflow soundness | `STATE_UNREACHABLE`, `MANAGED_FIELD_WRITABLE` (a PATCH exposes `status`), `TIMER_CYCLE`, `ACTION_NO_SCENARIO`, `GUARD_NO_FAILURE_SCENARIO` |
| 5 | Fidelity lint | plural nouns in paths, 201 on create, 404/409/422 semantics, `created_at`/`updated_at` present, list envelope consistent, conformance diff against the spec slice for OpenAPI input |
| 6 | Scenarios (inline `given:`) | `SCENARIO_STATUS`, `SCENARIO_ASSERT`, `SCENARIO_NOT_ATOMIC` |
| 7 | Seed | materialize through the enforce layer; `SEED_FK`, `STATE_INVARIANT`, plausibility (every state present, none >70%, causal timestamps, distinct ratio of free text ≥0.6, no duplicate person names, main entity ≥10× page size), `LOCK_HASH_MISMATCH` |
| 8 | Task lint | `REF_ADMIN_ROUTE`, `REF_UNGROUNDED_ID` (a written ID is neither captured nor in the instruction), `GATE_COVERAGE`, `TIMER_HORIZON` (a timer's `when` evaluated at setup end + 200 ticks flips seed rows), `TIER_MISSING`, `DIFFICULTY_MISMATCH` |
| 9 | Verify | §7 |

Each error is JSON:

```json
{"code":"UNKNOWN_ENUM_VALUE","owner_stage":"logic",
 "path":"workflows.ticket_lifecycle.timers.sla_breach.when","loc":"logic.yaml:71:9",
 "message":"'opened' is not a value of Ticket.status","expected":["new","open","escalated","resolved"],
 "actual":"opened","hint":"did you mean 'open'?"}
```

`--upto model|api|logic|seed|tasks` checks stage by stage. Each code has a fixed template and hint, and syrupy snapshot tests cover both.

### Serve

- `wengine serve <world>` loads the world, builds the DDL and restores a pristine snapshot.
- The public port serves the world API, `/openapi.json`, and bearer auth.
- List endpoints support the configured page style (cursor, offset or Stripe-style `starting_after`/`has_more`), parent-scoped routes (`/customers/{id}/tickets`) and an optional `Idempotency-Key`.

### Enforce

Each request runs as one `BEGIN IMMEDIATE` transaction under a global lock, in this order:
1. Validate input.
2. Check readonly and managed fields.
3. Check guards.
4. Apply effects.
5. Validate every touched row: type, required, unique, FK, checks, state invariant for the new state.
6. Cascade.
7. Advance the clock.
8. Fire due timers. Each timer runs in its own transaction, tagged `timer`.
9. Commit.

Any failure rolls the whole transaction back and returns a 4xx in the world's envelope, and the clock does not advance. A Hypothesis property test fuzzes call sequences and asserts that each failed call leaves the state hash and the clock unchanged. Concurrency is serialized by the lock, and the log `seq` is the commit order.

### Deterministic

- Virtual clock as described in §2.
- Per-entity ID counters live in the DB and are restored on reset.
- Lists have a total order with an `id` tiebreaker.
- Cursors are base64 of canonical `[sortkey, id]`.
- Runtime has no randomness.
- The seed uses per-entity hashlib streams.
- Faker version is pinned, and the lock file is canonical.
- Money uses integer minor units.
- Canonical JSON uses sorted keys and RFC 3339 UTC.
- `LIKE` search uses an engine-side casefold column, so it isn't limited to ASCII.
- CI runs everything twice and compares hashes.

### Inspect and reset

- `POST /reset` (backup API, a few milliseconds)
- `GET/POST /clock`, `POST /grade?task=`, `GET /hash`, `POST /setup?task=`

The CLI mirrors all of these.

### Grade

- `grade(task, state, journal)` evaluates the checks and gates. Gates read only the journal's agent and cascade changes.
- The verify harness drives the ASGI app in process.

## 6. WorldGen

### Stages

| # | Input | LLM output | Engine check (judge) | Repair policy |
|---|---|---|---|---|
| 0 Ingest | Raw input | none: deterministic code produces an `InputBrief`. OpenAPI: resolve `$ref` (circular refs cut at depth 2), flatten `allOf`, build an op index, narrow by `--include` or by a cheap-model pick capped at 25 ops when the spec has more than 40 ops, compute the schema closure, infer CRUD, log dropped ops. CSV: profile types, nulls, cardinality, keys, enum candidates (≤20 values covering ≥99% of rows), FKs by overlap ≥0.95, PII flags, plus 15 stratified sample rows | Code validation (spec parses; CSV has a header) | No LLM; hard fail with a message |

| 2 Model+API | Plan, format schema excerpt, spec slice or profile | `model.yaml`, `api.yaml` (keyed objects) | `check --upto api`, conformance diff, plan coverage (every planned item exists) | Up to 4 |
| 3 Logic | Plan, model, API | `logic.yaml` with scenarios and `given:` fixtures | `check --upto logic` (types, soundness, scenarios run) | Up to 5; can `amend` model/api |
| 4 Seed | Plan, model, logic | `seed.yaml`; `pools.yaml` from the cheap model | `check --upto seed` (materialize, invariants, plausibility) | Up to 4; `amend` logic if an invariant conflicts |
| 5 Tasks | Plan tasks, API summary, anchor index, `query_seed(entity, where)` tool | `tasks.yaml` (instruction, setup, targets, grader, reference) | Task lint, then `verify` per task (in parallel) | Up to 4 per task; a task is dropped only if ≥3 remain with all tiers covered, and the drop is reported |
| 6 Report | All artifacts plus engine JSON | A short narrative (≤200 words). Everything else comes from a template over data | none; `verify` output is pasted verbatim | none |

### Repair loop

1. Group errors by object key, then send the model the failing objects, the errors, catalog entries for those codes, the relevant schema excerpt and the plan excerpt.
2. The model calls `replace_object(key, yaml)` or `search_replace(key, old, new)`. Code applies the edit, then the stage check runs again.
3. **Fingerprint:** the sorted set of `(code, path)`. If a fingerprint repeats, the loop switches to a full rewrite of the stage file with the history of past fingerprints included ("you tried X, which caused Y").
4. **Regression revert:** an edit that adds errors at untouched paths is reverted automatically and counts as an attempt.
5. **Stall:** if the error count does not drop for 2 attempts, the stage moves to the `repair_escalation` model, once.
6. **Backtracking:** if at least half of the errors have an upstream `owner_stage`, the loop calls `amend(stage, object_key, yaml, reason)`. Code then re-checks the upstream stage and every downstream stage already built. The reason is appended to `assumptions`. Budget: `max_backtracks = 2`.

### Stop conditions

- A stage runs out of attempts.
- The global USD cap is reached (default $6).
- The wall-clock cap is reached (default 15 min).
- The backtrack budget runs out.
- An ingest fails hard.
- The plan linter finds the request is not a stateful API, e.g. "a real-time video codec".

In each case the output goes to `<out>.FAILED/` with `FAILURE.md`: the stuck stage, the last errors, the fingerprint history, what was tried, the suspected cause and a suggested narrower request. The exit code is non-zero, and nothing is ever written to `<out>`. Scope shedding is allowed only for items the plan marks optional.

### Iteration mode

`worldgen update worlds/x "add refunds"`:
1. Load the world and run `verify` to set a baseline.
2. The model writes a `plan_delta`, shown as a diff in `plan.md`.
3. Impact analysis in code walks the ID dependency graph to find which objects are affected.
4. Only affected stages re-run, in edit mode. Unaffected objects are shown to the model read-only.
5. Seed migration: lock rows stay byte-identical. New fields are backfilled from new per-field streams. New entities draw FKs from existing rows. New anchors get new IDs.
6. **Regression gate:** every old task's verify results (noop, ref, mutants) must be unchanged unless the delta names the task.
7. `world.yaml` version is bumped and REPORT.md gets a "Changes in vN" section.

### Input types

| Input | Handling |
|---|---|
| Description | Passed through. The plan names a real-world analog and fills gaps through assumptions. |
| OpenAPI | Paths, shapes, status codes, error envelope and page style follow the spec. `--include tag:X,path:/v1/charges*` narrows it. Undocumented transitions are invented and recorded as assumptions. |
| CSV (one or more files) | The model gets the profile only. Real rows become anchors and value pools, cleaned and keyed, then extended by generators fitted to the profile. |

Detection is by extension or sniffing, with `--input-type` to override.

### Observability

- `run.jsonl` records stage start/end, each LLM call (role, model, tokens in/out/cached, $, latency, transcript path), each check result, each repair attempt (fingerprint, error count, mode, outcome), amends, drops and totals.
- A live rich panel shows the stage, attempt number, $ so far and elapsed time.
- REPORT.md gets per-stage tables of time, cost and repairs.
- Checkpoints in `.stages/N/` support `--resume`.

## 7. Graders and tasks

**Difficulty ladder.** The lint infers tiers from the reference's structure, and every world needs at least one task per tier:
- **Easy:** at most one search and one write; the target is identifiable from the instruction.
- **Medium:** search or filter, then a workflow action (a managed transition through an action route).
- **Hard:** at least one of:
  - `paginate_all` or `foreach` where some target is beyond page 1
  - writes to two or more entities
  - `setup.advance_clock` plus reasoning about timers or derived state
  
  Hard tasks are graded by set equality.

**Verify suite.** Each step runs from a fresh reset plus setup:

| ID | Run | Must score |
|---|---|---|
| V1 | Reference (all `expect` statuses hold) | 1.0 |
| V2 | Noop; also **each check individually false after setup** (`GRADER_TRIVIAL`) | 0.0 |
| V3 | Every strict prefix of the reference's writes (writes marked `optional` are exempt) | < 1 |
| V4 | Overbroad: the last write action applied to up to 3 extra rows from the last list capture | 0 (gate) |
| V5 | Wrong target: a captured ID swapped for a seeded-RNG sibling | < 1 |
| V6 | First page only (when the reference uses `paginate_all` or `foreach`) | < 1 |
| V7 | Double run of the write steps (only if the state hash changes) | < 1 |
| V8 | **Alternative valid solution** generated by the engine: independent writes reordered, list calls with a different page size or sort, extra harmless reads | 1.0 |
| V9 | Determinism: V1 twice | identical hash and score |
| V10 | Seed noise: V1 with 20 extra ticks of clock before the agent starts | 1.0 (catches graders sensitive to timers) |

**Mutant validity filter.** A mutant is valid only if every call returns 2xx and its end-state hash differs from the reference's. If not, the engine tries up to 3 other siblings and otherwise logs the mutant as N/A. V3 plus at least one of V4–V6 must be applicable, or the task fails with `TASK_UNDISCRIMINATED`.

**Grader rules:**
- Checks assert outcomes, not paths. Free-text checks are allowed only when the instruction demands the text.
- Process checks (e.g. "used the escalate action") are mostly unnecessary, because `managed_by` already rejects a PATCH that tries to force the status.

## 9. Testing and live-run rehearsal

**Engine tests:**
- One fixture per error code, snapshotting code, path and message.
- CRUD, paging and filter edge cases.
- Hypothesis atomicity: failed calls leave the hash and the clock unchanged.
- State machine legality, including PATCH on a managed field returning 422.
- Timer ordering under clock jumps.
- Reset hash equals seed hash.
- Double-run hash equality.
- Origin tagging, i.e. timer changes are excluded from gates.
- Each verify mutant on known-bad graders: additive collateral, a check that is trivially true, a hardcoded first-page target. These must fail verify.

**Golden world:** helpdesk `verify` runs in CI and its dump and diff are snapshotted.

## 10. Risk register

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Repair loop oscillates or doesn't converge on unseen domains | High | High | Typed checks, keyed edits, fingerprints, revert, stall escalation, `amend`, per-code hints tuned on the stress suite |
| The declarative DSL can't express a workflow (proration, aggregates) | Med | High | Rich builtins (`sum`, `count`, `min`, `max`, `lookup`, `exists`, `ids`, date math, `foreach` effects); plan stage scopes workflows to what the DSL can express; the gap is recorded in out_of_scope |
| Timers change rows during a run and break gates | Med | High | Origin-tagged journal, `TIMER_HORIZON` lint, V10 seed-noise check |
| Mutants are invalid or have no effect, causing false verify failures | High | Med | Validity filter (all 2xx, hash differs), sibling retry, N/A logging, minimum applicability rule |
| Graders overfit to the reference | Med | Med | V8 alternative solution, outcome-only checks, free-text lint |
| Tasks are unsolvable through the public API | Med | High | Public-only references, `REF_UNGROUNDED_ID`, clock moves only in setup |
| Seed is implausible or inconsistent | Med | Med | Per-state invariants, derived history, plausibility lint, pools from the cheap model |
| Existing tasks break after `update` | Med | High | Per-entity streams, canonical lock, regression gate, anchors |
| Large or broken OpenAPI specs | Med | Med | Deterministic ingest, op index, 25-op cap, dropped-ops log, graceful degradation |
| Structured-output schema limits | Med | Med | Shallow tool schema, expressions as strings, engine validates |
| Live run exceeds time or cost | Med | High | Parallel in-process verify, caching, cheap model for pools and narrowing, hard caps, honest stop |
| Engine scope creep eats WorldGen time | High | High | Freeze at end of D3; only fixes found by the stress suite after that |
| Determinism leaks (floats, Faker drift, hashing) | Low | High | Minor units, pinned Faker, canonical JSON, CI double-run |
| The model escapes its sandbox or edits the engine | Low | High | No generated code; edit-tool path allowlist; engine pinned in `world.yaml` |

## 12. Decisions and assumptions log (seed for DECISIONS.md)

- **D-01** Python 3.12 and in-memory SQLite. Atomicity comes from DB transactions, not hand-rolled undo.
- **D-02** Worlds are YAML directories. Every collection is a map keyed by name. Expressions are strings.
- **D-03** Generated worlds use declarative logic only. There is no generated Python, and the `py:` hatch is COULD and limited to hand-built worlds.
- **D-04** Expressions are type-checked at check time. `lookup` is Optional and must be handled with `??` or `exists`.
- **D-05** Fields marked `managed_by` can change only through workflow actions. A PATCH that tries returns 422.
- **D-06** Clock: +1s per committed write. Reads and failed calls don't advance it. Jumps happen only through admin or task setup, and timers fire in chronological order.
- **D-07** The journal tags each change with its origin. Collateral gates ignore changes made by timers.
- **D-08** IDs are `PREFIX-NNNN` from per-entity counters. Lists are totally ordered with an id tiebreak. Default paging is cursor-based, 25 per page (max 100), unless the spec says otherwise.
- **D-09** Admin runs on a separate port. The public port serves the world API and `/openapi.json`.
- **D-10** The seed is a spec plus per-entity hashlib RNG streams. The lock file is canonical, and existing rows are never regenerated.
- **D-11** v1 seeds use state-conditional generation, per-state invariants and derived history. Simulation is SHOULD.
- **D-12** Score = Σ w·check × Π gates. Each check is false after setup. Collateral defaults to the whole world unchanged except declared patterns.
- **D-13** References use only public routes, with `capture`, `foreach` and `paginate_all`. Every written ID must come from a capture or the instruction. Clock moves belong in `setup`.
- **D-14** Mutants are generated only by the engine and pass through the validity filter. There are no decoys written by the LLM.
- **D-15** Verify runs in process over ASGI and resets through the backup API.
- **D-16** Money uses integer minor units. Canonical JSON uses sorted keys and UTC RFC 3339.
- **D-17** Non-interactive by default. Open questions get default answers in `plan.md`.
- **D-18** Pass or fail comes only from the engine's exit code or JSON. WorldGen cannot write to `engine/`.
- **D-19** A failed build goes to `<out>.FAILED/` with `FAILURE.md` and a non-zero exit.
- **D-20** Errors use the world's envelope. For description input the default is `{error:{code,message,field}}`; for OpenAPI input, the spec's error schema.
- **D-21** Auth is a static bearer token. `X-Actor` is used only when the workflow needs roles.
- **D-22** Answer-graded (read-only) tasks are out of scope for v1, pending the hiring team's reply.
- **D-23** For OpenAPI input with no narrowing flag, a cheap model picks up to 25 operations, and the dropped operations are listed in the report.
- **D-24** Temperature stays at the provider default. Reproducibility comes from the engine and the lock files, not from the model.
