# Spec calls: engine-check-core

- `layer.blocked` goes only to a section that is non-empty, has no issue in the report yet, and is read by at least one skipped layer. Its path is `[section]` and `found` lists the skipped layers that read it. The sections each layer reads are `LAYER_SECTIONS` in check.ts (references: entities, routes, actions, seed; compile: actions, jobs, seed, tests, tasks; seed, tests and tasks: their own section; lints: none, because lints only warn). Why: the header comment asks for one blocked issue per skipped section, and acceptance 4 asks for exactly one issue on a ref typo; an empty section has nothing to check, and a section that already has an issue would get a second one. Reversible: yes.
- Acceptance 4 ("path ending in the field") is met with the exact path of the bad value, `['entities', E, 'fields', F, 'entity']`, and the acceptance test uses a small inline world (customer and ticket only), so no later-layer section is non-empty. On bareWorld the same typo also blocks actions, jobs and seed. Why: every other issue path points at the value to fix (zod paths do too), and AGENTS.md says to use an inline world to trigger one issue code. Reversible: yes.
- A ref edge counts toward `seed.cycle` unless the field is `nullable: true` and not `required`, the same rule store.ts uses for nullify. Self-refs count. One issue per strongly connected group, at the first ref field of the shortest cycle from the group's first entity in declaration order. Why: acceptance 2 says "no nullable ref", and store.ts treats a required ref as never null. Reversible: yes.
- `route.duplicate_path` compares method plus path with param names dropped, so `/tickets/{id}` and `/tickets/{ticket_id}` collide. Routes come before actions, each in declaration order, and the later item gets the issue. Why: two such routes are ambiguous to the router. Reversible: yes.
- List routes may filter, search and sort on `id`, `created_at` and `updated_at` as well as declared fields. The `known` hint lists declared fields first, then those three. Why: the format says these fields are implicit on every row. Whether a text field is filterable is left to the API layer or a lint. Reversible: yes.
- `ref.unknown` also covers `actions.*.input.*.entity` (a ref field) and seed keys that name no entity (`['seed', X]`). Why: both are entity references, and the seed layer would otherwise fail on them. Reversible: yes.
- `state.bad_machine` paths: `initial` for a bad initial, `transitions.<from>` for an undeclared from-state, `transitions.<from>.<i>` for an undeclared target, `states.<i>` for each unreachable state. Reachability is skipped when initial is not declared. Why: each path is the value a model must change. Reversible: yes.
- A SnippetHost that throws is reported as `snippet.compile_error` at that snippet's path with the thrown message as hint. A world input whose getters throw is reported as one `schema.invalid` at `['format']`. Why: `check` is total. Reversible: yes.
- Within the references layer, issues are ordered entities (ref fields and state machines), seed cycles, routes, action inputs, seed keys, then duplicate paths. Within compile they follow SECTIONS order, then key order, then grader, solution, decoys. Reversible: yes.
