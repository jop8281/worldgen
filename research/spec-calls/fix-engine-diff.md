# Spec calls: fix-engine-diff

Reproduction at factory/integration 0384b27 (code-f4 probes-b/p5.ts): all six narrowing cases reproduced as non-destructive (enum value removed, state field to string, optional to required, new required action input, route path change, action method change), and a pure transition widening was destructive `transition_changed`. None was unreproduced. The fixtures NaN and job `every: 0s` lines in the same probe belong to other units and are left unchanged.

- New kinds, all in `DESTRUCTIVE`: `enum_value_removed`, `field_required`, `required_field_added`, `endpoint_changed`. New non-destructive kind: `transition_added`. Why: acceptance 1 and 2. A separate kind per narrowing keeps REPORT.md readable and lets the iterate gate name the cause. Reversible: yes.
- Removed enum values use the same rule as removed states: one `enum_value_removed` per dropped value at `[..., 'values', i]` (i = index in `before`), plus one `field_changed` at `values` only when added or reordered values remain. Why: one mechanism (`diffMembers`) for both ordered name lists. Reversible: yes.
- A `state` field whose type changes reports `field_changed` with both definitions, then `state_removed` for every state it had and `transition_changed` (before only) for every non-empty from-list. Empty from-lists are skipped, because a missing from-state equals an empty list. Why: acceptance 1 asks for lost states and transitions to be visible. Reversible: yes.
- Other type changes (string to text, int to string) stay non-destructive `field_changed`. Why: acceptance lists only the state case and the work order puts anything unlisted out of scope. Open question for the iterate gate owner: a type change can invalidate stored rows. Reversible: yes.
- `field_required` is emitted for `required` going from not-true to true, on entity fields and action input alike, and also when it happens together with a type change. Required to optional stays `field_changed`. Reversible: yes.
- `required_field_added` applies to new entity fields as well as new action inputs, because both use the same field rules (engine-diff spec call) and a new required entity field breaks existing create calls the same way. A field with a `default` still counts. Why: the classifier stays structural. Reversible: yes.
- `endpoint_changed` covers `method` and `path` of routes and actions. Route `op`, `entity` and `pageSize` stay `item_changed`. Reversible: yes.
- Transitions: target sets per from-state. If `before` is a subset of `after` the kind is `transition_added`. Any removed target, including a mixed add and remove, is `transition_changed`. This supersedes the engine-diff call that `transition_changed` stays destructive even when it only adds a target. Reversible: yes.
- Existing tests updated in diff.test.ts: R4 (edges into a new state) and R5 (added target) now expect `transition_added`; R10 expects `enum_value_removed ... values 1` and `endpoint_changed routes get_ticket path`. These assert the stronger classification. No assertion was dropped.
