# Spec calls: wg-cli-run

- Call: the default transport is `claude-cli`, from `worldgen.config.json`, and `--transport` overrides it. The chosen transport goes into the config overrides, so `transportOf(config)` drives both `makeModel` and the `transport` field of `run_started`. `--transport sdk` reads `LLM_KEY` (or `apiKeyEnv`) from the environment only, and nothing reads `.env`. Why: section N of the backlog item (U-11) replaces acceptance 3's ANTHROPIC_API_KEY line, and config.ts already refuses `ANTHROPIC_*` as `apiKeyEnv`. Reversible: yes.
- Call: `run_started` gains an optional `transport` field, and run.ts always sets it. It is optional so that event logs and test literals written before YOS-35 still type-check. Why: section N says the first run event records the transport. Reversible: yes. A later unit can make it required.
- Call: `makeModel` checks that the claude binary exists before returning a `claude-cli` model. It accepts a path to an executable file or a bare name found on `PATH`. A missing binary throws one line naming `claudeBin` and the sdk fallback. The eval CLI gets the same check. Why: the CLI must exit 2 before any work when the claude binary is missing. Without the check, the run would start and only fail at the first attempt as a `model_error` stop. Reversible: yes.
- Call: every failure before the run exits 2 with one line. That covers usage errors, `--world` before iterate lands, an `--out` that already holds `world.yaml`, a config that does not load, a missing binary or key, and an example world that does not check. A usage error line ends with `(see --help)`, and the full usage is printed only by `--help`. Why: the backlog item says "exits 2 before any work", and one line is easy to grep and to assert. Reversible: yes.
- Call: exit 1 covers a stop (the CLI prints `stopped: <describeStop(reason)>` on stderr) and also a crash thrown out of runWorldGen (it prints `worldgen crashed: <message>`). Why: neither one is done, and a crash is not a usage error. Reversible: yes.
- Call: `describeStop` lives in events.ts, next to `StopReason`. It prints the kind first, then what that kind carries, and lists at most five distinct issue codes. Why: the CLI holds wiring only, and events.ts owns the stop vocabulary and its console view. Reversible: yes.
- Call: the console view is `createEmitter(null, { console: true, progress: true })`. A null `runDir` writes no file, because runWorldGen already writes `events.jsonl` under `<out>/runs/<runId>/`. `progress` changes only the attempt line, to `<step> attempt <n>: <outcome>, $<cumulative> spent, <s>s elapsed`, where elapsed comes from event timestamps measured from `run_started`. The default summary view is unchanged, so the eval CLI's output stays the same. Why: the unit asks for one line per attempt with step, attempt, cumulative $ and elapsed time, and the eval console tests pin the old format. Reversible: yes.
- Call: the default `--out` is `../prod/worlds/generated/<slug>`, resolved from `code/`. `inputSlug` lives in input.ts: lowercase ASCII words joined by `-`, at most 40 characters, cut at a word boundary. A description uses its words, OpenAPI uses the file stem plus the `--only` prefixes, CSV uses its first file's stem, and the fallback is `world`. Why: the unit names this default, and input.ts owns input kinds. Reversible: yes.
- Call: test/worlds.test.ts now checks each `prod/worlds/generated/<name>` as a world and no longer treats `generated/` itself as one. Why: without this, the first default run would fail `npm test` on a directory that holds worlds rather than being one. Note that a stopped run left under `generated/` still fails `npm test`, as AGENTS.md intends for anything in prod/. Reversible: yes.
- Call: the CLI refuses (exit 2) an `--out` that already holds `world.yaml`, and points to `--world`. Why: create mode would overwrite that world, and the golden helpdesk is one `--out` typo away. Iterate is the way to change an existing world. Reversible: yes.
- Call: REPORT.md is written by the CLI unless this run wrote it, meaning it is absent or its mtime has not changed since before the run. A stale REPORT.md from an earlier run is replaced. The plan is read back from `plan.yaml` through the new `parsePlanYaml` (plan.ts), and only when this run emitted `step_finished` for `plan`, so an older plan.yaml is never reported as this run's plan. Why: the unit says to write REPORT.md when runWorldGen does not, and a stale report would describe a different run. Reversible: yes. Once run.ts writes REPORT.md itself (wg-repair-full), the CLI's write is skipped automatically.
- Call: `--world <dir> "<change request>"` is parsed and validated (no `--out`, no `--openapi` or `--csv`, and a non-empty request), then refused with exit 2 and `iterate mode lands with YOS-52`. Why: run.ts has the `iterate` Job kind but throws `not implemented` for it. Reversible: yes. YOS-52 replaces the refusal with `{ kind: 'iterate', worldDir, request }`.
- Call: flags take their value as the next argument. The `--flag=value` form is not accepted, and parseInputArgs's other skipped options (`--max-repairs`, `--upto`, ...) are unknown options here. Why: the same convention as the eval CLI, and an option that does nothing should fail rather than be silently ignored. Reversible: yes.
- Call: the config is loaded from `code/worldgen.config.json` by absolute path, not from the cwd. Why: the eval CLI does the same, and `npm run` from another directory would otherwise miss it. Reversible: yes.
