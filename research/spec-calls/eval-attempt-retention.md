# YOS-136: eval attempt retention

- Before running a case again, rename its existing directory into `.attempts/<case>/attempt-*/artifacts` under the same run directory. The old directory is not parsed, rewritten or deleted. New output keeps the existing `<run>/<case>/case.json`, events and world paths, and summary collection continues to use only those latest-case paths. Absolute paths inside retained logs remain historical. Reversible: stop producing new history without removing existing archives.
- Each case has an exclusive `.attempts/<case>/active.lock` containing the process PID. Ownership spans retention, generation and case/summary publication; a competing same-case run fails before it writes. This is per-case protection, not a whole-suite summary lock: different cases must not be run concurrently into the same run directory. Reversible: replace this coordination mechanism while preserving artifacts.
- A killed process leaves its lock and partial latest output intact. Before retrying, the operator must confirm that process has stopped, inspect the retained and latest paths, and remove only that case's `active.lock`; the next run retains partial output too. Locks are never stolen automatically. A preparation error after rename names the retained recovery path. Retention errors fail the eval before new work; symlink/non-directory run, history and case storage is refused. No automatic history pruning or power-loss durability guarantee is introduced.
- This is offline evidence preservation for YOS-53, not a completed stress suite or live-provider qualification. Provider execution, engine behavior, metering, budgets and prompt tuning are unchanged. Record the decision centrally during integration; the coordinator owns `research/decisions.md` numbering.
