# Spec calls: boat-sdk (YOS-75)

- `waitReady` treats `ready`, `idle` and `running` as ready, and `error`, `archived`, `archiving` and `cancelled` as terminal. Why: the SDK's own `waitUntilReady` uses that set, and `cancelled` would otherwise poll until the timeout. It times out after sleeping `readyTimeoutMs` (default 300000), so tests drive it with an injected `sleep`. Reversible: yes.
- `stop` accepts an actual HTTP 404 as already removed. Boat rejects a repeated stop of an archived sandbox with HTTP 400; that response is accepted only after a new GET proves the sandbox archived or removed. `waitStopped` returns once the state is `archived`, or an actual HTTP 404 or `cancelled` says boat.dev removed the sandbox. The SDK response status determines removal; body text mentioning 404 never does. `error` while stopping is a failure, since the sandbox may still be billed. `down` is stop then `waitStopped`, including repeated cleanup, so the final state is verified. It never deletes: delete is irreversible and needs a confirm header. Reversible: yes.
- Files go under the absolute root `/tmp/worldgen`, with one `mkdir -p` of every parent directory before the uploads. Why: the sandbox's home directory is unknown, and the API does not say whether `writeFile` creates parent directories. A real smoke may show a better root. Reversible: yes.
- Node is accepted when `node -v` reports major 22 or newer. Otherwise NodeSource `setup_22.x` is installed, with `sudo` only when not root, and `node -v` is checked again. Reversible: yes.
- Commands run with a timeout capped at 600 s (the API's limit). A timed-out command reports exit 124, and a command killed by a signal reports exit 1. Reversible: yes.
- Failures become one-line errors: `boat.dev <op> failed: HTTP <status> <first 300 chars of body>`, or the network cause with its errno code. The key is scrubbed from every message, and the SDK error is not attached as `cause`. The backend turns each `BoatError` into a `SandboxError` with the same text. Reversible: yes.
- On failure after create, the original error is rethrown unchanged once the VM is stopped and verified. If cleanup also fails, the error names both, so a leaked sandbox is never silent. A failed `create` has nothing to stop. Reversible: yes.
- The machine type comes from the requested size (`small` 2 CPU and 4 GB by default, `default`, `large`). A size boat does not sell is refused with the list of types that exist. Reversible: yes.
- Only the world port is exposed, publicly, through `upWorld()`. The admin port is never passed to `expose`. Reversible: yes.
- Boat serves the world with `--host 0.0.0.0` for public and authenticated proxy URLs, because both proxies reach the box over its network address. A loopback world bind produced HTTP 502 in live tests. Admin defaults to `127.0.0.1`; the separate `--admin-host` option is not passed by the Boat startup recipe. Only the world port is exposed. Registry startup uses `reachWorld` to require HTTP 200 from `<url>/openapi.json` within the readiness deadline; direct `upWorld` callers must supply the readiness callback. Failure collects the serve log and tears down the sandbox. Reversible: yes.
