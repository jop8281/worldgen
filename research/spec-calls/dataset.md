# Spec calls: dataset (YOS-91)

Code: `code/src/dataset/` (`schema.ts`, `episode.ts`, `solver.ts`, `store.ts`, `pipeline.ts`), `code/src/cli/dataset.ts`, run with `npm run dataset -- --world <dir> --out <dir> --run-id <id> --engine-commit <sha> --max-turns <n> --budget-usd <n> --max-minutes <n>`. Provider and sandbox follow `research/boat-sonnet-dataset-plan.md`: pinned `claude-sonnet-5-5` through the injected `Model` from `cli/models.ts` (`claude -p` by default, the SDK only on opt-in, A-66 and A-80), Boat only, deterministic engine grading. Nothing here was run against live services.

## Episode and schema

- One strict, versioned `Episode` record (`schema_version` 1) per task attempt, with a message list instead of a second copy of the tool calls. Messages are numbered from 0 and are `instruction`, `tool_call`, `tool_result` and `final_reply`. Every call is followed by its result under the same `call_id` (`c1`, `c2`, ...). A call without a result, an orphan result, a reused id, a second instruction, or a final reply that is not last is refused when the record is made and again when it is read. `final_reply` must equal the last message's text, or be null. Why: one list cannot disagree with itself, and pairing is checkable. Reversible: yes.
- `episode_id` is `<run_id>__<task_id>__<n>`, `n` being 1 (one episode per task per run). Why: stable, readable, safe as a file name. Reversible: yes.
- A tool result has an `outcome`: `response` (the world answered), `rejected` (the controller refused the request before sending it) or `error` (it could not be sent or read). Rejected and failed calls stay in the record, so the solver's history matches what it saw. Reversible: yes.
- Stop reasons: `done`, `turn_limit`, `budget_limit`, `time_limit`, `model_error`, `world_error`, `grade_error` and `interrupted` (Ctrl-C). The last one is an addition to the plan's list: calling an operator abort a time limit would be wrong. Reversible: yes.
- A complete success is exactly: stop `done`, engine score 1, a non-blank final reply, both state hashes, no error, at least one model call, no call of unknown cost, and cost above zero. `dataset.jsonl` holds only those. Everything else, including a confident reply the engine scored 0, goes to `failures.jsonl`. Reopening an export rejects a success in the failures file and a non-success in the dataset file. Why: a zero-cost "success" can only be invented. Reversible: yes.
- Records carry `score_scope: engine_state_only`, and the manifest and `REPORT.md` repeat that the engine grade does not certify the factual claims in the final reply (plan: "preserve that distinction"). Reversible: yes.
- Hashes: `hashState` is sha-256 over canonical JSON (keys in code-unit order, no whitespace, `undefined` dropped, non-finite numbers and non-plain objects refused) of the engine's state dump. Initial and final hashes are null only on episodes that never reached the world (budget or time spent before the start, or a failed reset). Reversible: yes.
- `world_version` is the sha-256 of the frozen `world.yaml`. The run checks the world, writes it with `saveWorld` to `private/worlds/<hash>/world.yaml`, rereads the bytes and requires the same hash. That frozen copy is what is uploaded, and the manifest names it by path and hash. The world file holds the graders and solutions, so it stays under `private/` and is never part of the export. Reversible: yes.
- `config_version` is `cfg-` plus 12 hex of the hash of the run limits (turns, budget, minutes); `prompt_version` is `solver-prompt-1` and must change with the prompt, tool schema or history rendering. Reversible: yes.

## Running an episode

- Before the sandbox is used, the world must pass the engine's `check` (all seven layers) and every task must have a verdict, i.e. be proven. A world with no tasks, or any unproven task, is refused. Reversible: yes.
- Every episode resets the world and reads the state, then compares its hash with the seed hash computed by a local engine from the checked world. A reset that lands elsewhere stops the episode as `world_error` before any model call. Why: the frozen seed is the contract, and the engine is the only judge of it. There is no task setup beyond the seed, and none is invented. Reversible: yes.
- The solver sees the visible instruction, the difficulty, `openApiOf(world)` and its own history. The CLI turns the metered Sonnet proposer into the narrow `NextTurn` function; the core never imports `llm.ts` or a model. One tool, `solver_turn`, either sends a request (method, path, query, body) or finishes with `final_reply`. The proposer takes one message, so the history is rendered into the prompt as text and the OpenAPI document goes in the system prompt. Only the model's text outside its tool call is kept, as `commentary`; thinking is never requested or exported. For the helpdesk the OpenAPI document is about 50 KB, so each turn pays for it again. Reversible: yes.
- Requests must be relative, start with one `/`, carry no `?` or `#` (query parameters go in `query`), and match a method and path documented in the OpenAPI document, where a `{placeholder}` takes one non-empty segment. Refused: absolute and protocol-relative URLs, backslashes, whitespace and control characters, empty segments (including a trailing slash), `.` and `..`, percent-encoded separators, backslashes and dots, double encoding, any segment starting with `_world` after decoding, undocumented paths and methods, a body on GET or DELETE, and a body over 100,000 characters. The root path `/` is allowed only when documented. Each refusal comes back to the solver with the reason, as a rejected tool result. Responses over 20,000 characters are cut and flagged `truncated`. Redirects are not followed. Reversible: yes.
- Public requests go over HTTP to the URL `upWorld` exposed. The admin routes are never exposed. The controller runs three small Node scripts inside the sandbox through `backend.exec`, passing every value as argv: one makes the admin request and prints its status, size and sha-256 (inline when under 30,000 bytes, otherwise it keeps the body in a file), one reports a file's size and hash, one returns a 48 KiB chunk as base64. The controller joins the chunks and requires the size and hash to match. A 400 KB state dump takes about nine reads. Reversible: yes.
- Errors at the private boundary (reset, state, grade, log) are kept in full, redacted, in `private/episodes/<id>/errors.json`. The public record says only which step failed and that the details are private, because the engine and the sandbox can quote grader or world text in their errors. Reversible: yes.
- Limits: `--max-turns` bounds model turns per episode; `--budget-usd` bounds model spend across the run (checked before each call, so one call can overshoot it); `--max-minutes` is a wall-clock deadline for the whole run. One `AbortController` per episode carries the deadline and the operator's interrupt, and when it aborts the solver rejects the pending turn at once; `Model` takes no signal, so the call itself ends at its own timeout. A call cancelled before the API reported usage, or lost to a network failure, counts in `usage.unaccounted_calls` (cost unknown, not zero). A billed malformed output is added to the usage. An API error with an HTTP status is not billed. Once the budget or the deadline is spent, later episodes are recorded as failures without resetting the world. Reversible: yes.
- After the stop, whatever its reason, the controller reads the final state, asks the engine for the score and reads the log. Grading is private and quick, so the deadline does not cancel it. If it fails, the episode is `grade_error` with no score (when it would have been `done`), or keeps its stop reason with the failure appended. The score never comes from the model. Reversible: yes.
- The engine's initial and final state dumps and call log are stored per episode under `private/episodes/<id>/`. A dump that holds a supplied secret is refused. Reopening an export checks the dumps of every accepted episode against the recorded hashes. Reversible: yes.

## Saved logs and export

- Each episode is appended to `logs/<run_id>.episodes.jsonl` and flushed as soon as it ends. Appending the same record again is a no-op, and a different record under the same id is refused. Reading a log fails closed on a truncated last line, a blank line, bad JSON or a record that fails the schema, naming the line. Reversible: yes.
- `exportDataset` reads every saved log under `--out`, so the export accumulates runs. It removes identical duplicates, fails on a conflicting duplicate, sorts by run, task and episode id, and writes `dataset.jsonl`, `failures.jsonl` and `manifest.json` with no timestamps. Exporting twice gives identical bytes. Optional run, task and episode id filters are recorded in the manifest, and a filter that matches nothing is an error. Reversible: yes.
- The manifest holds the schema, manifest, prompt and config versions, the engine commits, the run ids, the frozen world references (path and hash), counts by stop reason, and size, record count and sha-256 for each file. Files are written to a temporary directory, reopened and validated there, and moved into place with the manifest last, so a failed check leaves the earlier export alone. A second validation then runs on the final files. Validation checks sizes, checksums, canonical form, order, the success rule per file, duplicate ids across both files, counts, version lists, world hashes and the private state hashes. Reversible: yes.
- Supplied secrets (the two API keys, the world URL and the admin address) are redacted from every public string, error and diagnostic, and every file is checked for them before it is written or exported. The core never reads the environment: the CLI passes the values in. Reversible: yes.

## Boat lifecycle and result

- Order: preflight (offline, no key), freeze the world, `upWorld`, episodes one at a time, collect from the sandbox (serve log, final state, final call log, into `private/diagnostics/<run>/`), export and reopen, then `backend.down`. `down` is attempted on every path after the sandbox exists, including a failed export or collection. The Boat backend's `down` already polls until the provider reports it stopped. A failed stop is reported with the sandbox id and makes the run `failed`. If the sandbox never came up, `upWorld` has already cleaned up. Reversible: yes.
- The teardown guard starts before the post-start log and controller port setup. A logging failure after startup still attempts `down` once and preserves the redacted error. A logging failure after `down` has confirmed the stop records a separate problem while keeping `teardown: confirmed`. Logger errors fail the run without changing the known provider state. Reversible: yes.
- Collection errors are saved in `collect-errors.txt` next to what was collected, and make the run `failed`. If an episode's evidence or the report could not be written to the host, the run is `failed`. Diagnostics never enter the export. Reversible: yes.
- Status and exit code: `accepted` (0) means every task has a complete success, the export reopened clean, and the stop was confirmed. `incomplete` (3) means the pipeline is sound but some episodes failed; their rows are in `failures.jsonl`. `failed` (1) means a gate failed or the preflight refused. 2 is bad usage. A run with no solver successes writes an empty `dataset.jsonl` and is `incomplete`. Reversible: yes.
- Ctrl-C and SIGTERM cancel the pending call, record the episode as `interrupted`, skip the remaining tasks, still collect, export and stop the sandbox, and exit 1. The CLI passes `flushOnExit: false` to the backend registry so its exit hook cannot skip the teardown; a second signal exits at once. Reversible: yes.
- `REPORT.md` in `--out` lists each episode's stop reason, engine score and cost, and states the grading limit. It names how many problems there were, not their text, which is in the private summary. Reversible: yes.

## Open until a live run

- Whether `backend.exec` on Boat returns stdout large enough for the 48 KiB chunk (64 KiB of base64), how long each exec takes, and whether `npm ci` plus the serve start fit the 1800 s default TTL together with all episodes.
- The no-env isolation of the Boat sandbox belongs to the Boat owner. The upload holds only the code package and the frozen world, no key, but a live run must wait until the sandbox is known not to inherit any.
- A per-call cost ceiling before the call. `--budget-usd` is checked after each call.
- Live acceptance (YOS-91, YOS-108): a reopened export from a real Sonnet run on the helpdesk, with the sandbox stop recorded.
