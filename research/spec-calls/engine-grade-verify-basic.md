# Spec calls: engine-grade-verify-basic

- U-2 applied in part: verifyTask enforces solution exactly 1, noop exactly 0 and the replay hash. Decoys and strict prefixes stay with engine-verify-full, so a verdict carries `decoys: []` and `bestPrefixScore: null` until then. Reversible: yes.
- `verifyTask` takes a `CheckedWorld`, not a `World`. Why: it runs solutions through `runtime()`, which accepts only CheckedWorld, and the architecture test allows the cast only in check.ts; check.ts casts in its tasks layer exactly as it already does in its tests layer. Reversible: yes.
- `runtime(world, host, start?)` gains an optional start state; reset() returns to it. Why: verifyTask runs every solution from the seed check already built (A-41), and Runtime.grade needs the start state to grade against. Reversible: yes.
- `grade()` gains an optional sixth parameter `journal` (default empty). Why: ctx.changes() needs call/job origins (A-28), which only a runtime journal records; without one, every change counts as a call. Reversible: yes.
- `gradeDump(world, taskId, dump, host, journal?)` takes an optional runtime journal so ctx.changes() skips job changes (A-28 outranks treating every dump change as a call). Without a journal it cannot tell jobs from calls, so when any job's first firing (meta.clock.start + every) is at or before the dump's `now` the ok result carries a `caveat` naming the jobs and saying a collateral check may have lowered the score. Why: a StateDump carries no origins, and changing the dump format belongs to the CLI/HTTP owners; `worldplay grade --state` should pass a saved journal once it has one. Reversible: yes.
- `gradeDump` takes the host as a fourth parameter. Why: the grader and seed snippets must be compiled and run. It seeds the world itself (clock at meta.clock.start) and throws an Error starting `Not a state dump:` for a malformed dump, since no catalog code covers a bad grade input. Reversible: yes.
- An unknown task id in grade/verifyTask is `ref.unknown` with kind `task` at ['tasks', id]; Runtime.grade throws an Error naming the issue code, path and hint. Why: reuses the catalog, no new code. Reversible: yes.
- task.solution_not_full_marks and task.noop_not_zero sit at ['tasks', id]. Why: either the grader or the solution may be wrong; owner is `tasks` either way. Reversible: yes.
- A solution whose ctx.assert fails yields snippet.runtime_error at ['tasks', id, 'solution'] with message `ctx.assert failed: <msg>`. Why: test.failed names a world test; a solution that fails its own assert is a runtime failure of that snippet. Reversible: yes.
- When the grader faults on both the solution end state and the seed with the same code and found text, the issue is reported once. Why: one fix covers both. Reversible: yes.
- `clientCtx` moved from check.ts to tasks.ts (exported), and check.ts's tests layer imports it. Why: the work order says ClientCtx objects are built in tasks.ts; one builder keeps tests and solutions on the same api/assert/now. Reversible: yes.
- The grader's db and seed readers go through store `transact()` read views (nothing written). Why: `where` matching (canonical datetimes, omitted keys) then matches handlers exactly. Reversible: yes.
- Solution calls count toward `stats.unexercisedActions` (the tasks layer adds each verdict's first-run actions), as the Run comment in check.ts planned. Reversible: yes.
