- Redaction runs before the 8000-char cut, line by line, on the whole text (raw input capped at 200000 chars first). Why: a secret straddling the cut would leave a partial token; the 200000 cut backs up to the last whitespace so a partial token never survives below a mask pattern's length floor (masking can shrink text, moving the cut-off token into the 8000-char summary). Reversible: yes.
- No window splitting for long lines. Why: windows cut inside a long secret (a 7000-char token or quoted password, or a Cookie line) and the tail of it leaked into the digest; every pattern is linear or has a fixed cap, so one pass per line is already bounded (tested on 200KB adversarial lines). Reversible: yes.
- digestInput catches every throw and returns { ok: false, why }, so unimplemented openapi and csv kinds report "not implemented". Why: the CLI needs a value to print. Reversible: yes.
- parseInputArgs throws an Error on invalid argv (no input, mixed kinds, missing values). Why: it mirrors inputSchema.parse; argument errors belong at the CLI boundary. Reversible: yes.
- Several positional words join with one space into a single description. Why: unquoted shell descriptions still work. Reversible: yes.
- parseInputArgs skips the other worldgen CLI options so they never reach the description: value options --out, --world, --model, --budget-usd, --max-usd, --max-minutes, --max-repairs, --upto, --resume, --jobs, --verify-jobs, --thinking, --transport (U-11: cli by default, sdk opt-in); value-less flags --interactive, --pause-after-plan, --json, --allow-destructive; and the --opt=value form. Any other --flag throws. Why: an unknown flag must not leak into the description. Reversible: yes; the CLI unit extends the sets (a bare --resume without a value would swallow the next word).
- Secret patterns: Bearer tokens, sk-... keys, key/password/secret/token words followed by = or :, Authorization Basic/Digest, Cookie lines, ghp_/github_pat_, AKIA/ASIA, xox and JWT shapes, URI userinfo, PEM PRIVATE KEY blocks. Keyword secrets are masked with no prose exemption. Why: over-masking a word costs less than a leak; `\b` fails after `_`, so key names match without it. Reversible: yes.
- Call: redact() normalises first (NFKC, strip zero-width and soft-hyphen, fold Cyrillic/Greek lookalikes only inside mixed-script words, join CRLF, backslash continuations, and a credential label split from its value by a newline, and a sk- key wrapped onto a bare token line). Why: the 51 red-team cases need lookalike and split secrets masked; the digest text may therefore differ from the raw text in those characters. Reversible: yes, delete normalize().
- JWTs are masked by a dot-split scan (maskJwts) instead of one regex, because the three-segment regex backtracked quadratically (about 9.7s on 'eyJ-' repeated to 200KB). Why: linear time with the same coverage. Reversible: yes, swap back to a bounded regex.
