# Spec calls: wg-run-slice (YOS-34, covers YOS-74)

- Call: per-step model and effort live under a new top-level `stepModels` key (keyed by step id), next to `steps` (budgets), with `effort`, `escalate`, `transport`, `claudeBin` and `apiKeyEnv` as top-level keys. Why: red-team tests WG-C05 and WG-C07 deep-equal `steps` to `{maxAttempts}` only, so model fields cannot go inside `steps`. Reversible: yes.
- Call: every setting added here is optional in the parsed `Config`, and code applies its default (`transportOf`, `stepModel`, `claudeCliModel`). Why: `test/redteam-wg/fixtures.ts` and `test/policy.test.ts` build `Config` literals that a required field would break. Reversible: yes.
- Call: the shipped config names no model per step, only effort (high, high, xhigh, medium, xhigh, escalate max), and every step uses the top-level `model` (claude-opus-5-5). Why: models.json used opus everywhere, and leaving the model unpinned lets `--model` reach every step. Reversible: yes.
- Call: the every-model-is-priced rule is a parse error only when `transport` is `sdk`. Why: only the SDK path prices calls from `prices`, and the claude CLI reports `total_cost_usd` itself. WG-C05 and WG-C06 parse unpriced test models under the default transport. The error names the model and its path (`model`, `stepModels.<step>.model`, `escalate.model`). Reversible: yes.
- Call: the built-in price table moved to config.ts as `BUILTIN_PRICES`, and llm.ts re-exports it as `DEFAULT_PRICES`. Why: config validation must see built-in prices, and config.ts may not import llm.ts. Reversible: yes.
- Call: `apiKeyEnv` (default LLM_KEY) must look like an env var name and must not start with `ANTHROPIC_`. Why: U-10 and U-11 say never use the ambient Anthropic key. Reversible: yes.
- Call: `ProposeRequest` gains optional `model` and `effort`, and the `Model` interface is unchanged. The SDK path sends effort as `output_config.effort` and checks the request model's price before the network call. Why: per-step selection without a second Model per step. Reversible: yes.
- Call: a stall is a retry whose issue count is not lower than the previous attempt on the same step. From the next attempt on, that step visit uses `escalate` for whichever of model and effort it sets. Why: research describes a stall as "attempts without progress", and policy already stops on a repeated issue set, so counts are the remaining progress signal. Reversible: yes.
- Call: `claudeCliModel(config, spawn?, now?)` passes `-p --output-format json --model M [--effort E] --system-prompt S --json-schema J --tools "" --safe-mode --strict-mcp-config --disable-slash-commands --no-session-persistence`, with the prompt on stdin. It runs from the OS temp dir and inherits the environment. It never uses `--bare`, because `--bare` ignores the logged-in session. Why: U-11. Without `--safe-mode` and a neutral cwd, CLAUDE.md, hooks and MCP servers would reach WorldGen prompts. Reversible: yes.
- Call: one real smoke call (CLI 2.1.292, schema `{word: string}`, effort low) confirmed that `--json-schema` works with `--tools ""` and `--safe-mode`. The result held `structured_output: {word: "pong"}`, `subtype: success`, `num_turns: 2`, `total_cost_usd: 0.014896` and usage, and `result` was the same JSON as text. So advice drops a `result` equal to the JSON of `structured_output`. Reversible: yes.
- Call: the per-call timeout is `maxMinutes` (SIGTERM), and the run's own clock still stops at `maxMinutes` through policy. A missing `total_cost_usd` falls back to `costOf` when the model is priced, else 0. Why: no CLI timeout flag exists, and a missing cost must not look free when a price is known. Reversible: yes.
- Call: `runWorldGen` deps are `{ model, exampleWorld, emit?, now?, runId?, digest? }`. runWorldGen creates the `events.jsonl` emitter itself, and `emit` only observes. `digest` is a seam so tests can supply fixtures and an API shape before the csv and openapi adapters exist. Why: acceptance 3 and 5. Reversible: yes.
- Call: code owns `meta`. `name` comes from the output directory (`gen-helpdesk` becomes `gen_helpdesk`), `description` and `resembles` from the plan, and `api` from the digest. A stage edit with a non-empty `meta`, a section it does not own, an unknown section or an unknown edit key is `edit.out_of_scope`, and its outcome is `invalid_output`, so policy retries and never backtracks on it. Empty unowned parts (`tasks: {}`) are ignored. Why: acceptance 2 and 3. worldEditSchema silently strips unknown keys, so a typo would otherwise lose content. Reversible: yes.
- Call: plan.yaml is written for a refusal too, then the run stops with `input_rejected`. A plan that fails `planSchemaFor` is `invalid_output` with `schema.invalid` issues rooted at `plan`. Why: the refusal reason is kept on disk, and the plan step gets the same repair loop. Reversible: yes.
- Call: a stage whose only engine errors belong to later stages is accepted with the unchecked world. The last stage also blocks on deferred errors, so only a CheckedWorld is saved. Why: judge.ts says run.ts must clear deferred errors before it saves. Reversible: yes.
- Call: a retry prompt includes the rejected answer as JSON and says it was not applied. Why: the world in the prompt does not contain it, and a model that resends only a delta would lose the rest. Reversible: yes.
- Call: a `backtrack` decision moves the step pointer, records it with `recordBacktrack`, emits `backtracked`, and starts the target with the issues as feedback. The world is not rolled back. Why: the loop must handle every Decision. REPORT.md and richer backtracking stay with wg-repair-full. Reversible: yes.
- Call: an `advance` with `overspent` is not reported separately, because no RunEvent carries a warning. `run_finished.costUsd` above the budget shows it. Why: events.ts is outside this unit. Reversible: yes.
- Call: iterate mode throws `not implemented: iterate mode (wg-iterate)`. Why: out of scope. Reversible: yes.
