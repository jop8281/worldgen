# Spec calls: engine-lints

- Superseded by YOS-113: `world.too_few_tasks` is a `tasks`-layer error for any world with fewer than 3 tasks, 0 included. It follows the issues of failing tasks, so a model fixes broken tasks first. A world that fails it never reaches the lints layer, so lints run only on a world with at least 3 verified tasks. WorldGen stages before tasks (model, workflow, seed) still pass. `blockingIssues` defers the error to the tasks stage, and run.ts accepts a stage that is not last when it has no blocking issues. Cost: a 0-task world gets no lint warnings, so the seed stage's lint gate cannot fire before tasks exist. Reversible: yes.
- `tasks.difficulty_not_spread` (warning) lists the difficulties present in format order (easy, medium, hard). It is a lint, so it fires only on a world with 3 or more tasks that verify. Reversible: yes.
- `seed.too_few_rows_for_paging`: #104 (stab/paging) owns this rule. It warns when an entity with a list route and a create route has rows <= its largest list pageSize. Reversible: yes.
- `seed.state_mix_skewed` fires when a declared state has zero rows, or when one state holds strictly more than 70% of the rows that hold a declared state (integer math `n * 10 > total * 7`, so exactly 70% passes). It gives one issue per state field, at `['seed', entity]`. `found` joins every problem in declared state order with `; `, and the hint has the counts for every state. A null state value is not counted. A field where no row holds a state is skipped, because the paging lint already flags an empty listed table, and an unlisted entity that starts empty, such as one that tasks create, is not skewed. Why: this follows the spec's "believable mix of states" while keeping the seed stage from being blocked by a table that is meant to start empty. Reversible: yes.
- Tests that encoded the behavior from before #52 and YOS-113 are updated in this unit. They are listed in the PR body. Why: these are the intended outputs, not regressions. Reversible: yes.
- `world.read_only` fires once, at `['routes']`, when routes exist, none is create, update or delete, and the world has no action. A world with no routes yet is skipped. Why: an agent that can only read gives a grader no change to judge. Reversible: yes.
- `task.no_write` fires per verified task whose solution made no successful write, at `['tasks', id, 'solution']`. `TaskVerdict` gains `solutionWrites`, counted with the same rule as the prefix check. Why: a task the solution finishes by reading grades the clock or nothing. Reversible: yes.
- `seed.time_order` fires once per entity, on the first row in id order where `updated_at` is before `created_at` or either stamp is after `meta.clock.start`. Why: seeded history happened before the world starts. Only engine stamps are read, since a user datetime such as `sla_due_at` may sit in the future. Reversible: yes.
- `seed.totals_mismatch` is a naming rule: a numeric field `total` (parts named `amount`) or `<part>_total` on an entity, and a child entity with a ref to it and a numeric `<part>` field. It fires once per field pair, on the first parent row with child rows whose sum differs. Parents with no child rows are skipped. Why: the spec asks for internally consistent seed data, and this is the common shape that code can check without a model. Reversible: yes.
- `tasks.no_read_before_write` fires per verified medium or hard task whose solution makes no successful GET before its first write, at `['tasks', id, 'solution']`. `TaskVerdict` gains `solutionReadsBeforeWrite`. Easy tasks and solutions with no write are skipped (the second is `task.no_write`). Why: a solution that writes to ids it never looked up proves the task needs no discovery. Reversible: yes.
- `route.unused_required_input` fires per required action input whose name never appears as a word in the handler source, at `['actions', action, 'input', field]`. It is a text check, so a handler that reads inputs by computed key gets a false warning. Why: a caller must send the field, yet nothing uses it. The redteam base world's `escalate` handler now refuses a blank `reason`, because the lint was right about it. Reversible: yes.
- `seed.lorem_text` fires once per string or text field holding the word `lorem` or `ipsum`, with the count and the first value. Why: placeholder text is the cheapest sign of implausible values. Reversible: yes.
