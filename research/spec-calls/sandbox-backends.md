# Spec calls: sandbox-backends

- `SandboxBackend` is `{ kind, up(files, {name, size?, image?}) -> {id, workdir}, exec(id, argv, {workdir?, timeoutSec?}) -> {exitCode, stdout, stderr}, start(id, argv, {workdir?, log}), expose(id, port, {public}) -> url, down(id) }`. `up` returns the id, so a hosted backend (boat) can hand back a server-assigned id. The CLI backends use the caller's name as the id. Why: YOS-86 acceptance 1, shaped so `src/boat/*` can be adapted to it at merge time. Reversible: yes.
- A non-zero `exec` is a result. A failed CLI step (`create`, `forward`, `ports`, `delete`, `rm`) throws `SandboxError` carrying the last stderr line. Why: `upWorld` decides what counts as failure, and the backends stay thin. Reversible: yes.
- The `Runner` rejects only when the process cannot start. ENOENT becomes the one-line error `<bin> not found on PATH. Install it: <command>`. `nodeRunner` spawns with `shell: false`, and it resolves 500 ms after `exit` even when a daemonized grandchild (`openshell forward start -d`) still holds the pipes. Why: a child that inherits the pipes keeps `close` from ever firing. Reversible: yes.
- Bundle layout: the code package goes at the workdir root, and the world goes under `worlds/<basename>/`. `upWorld` runs `npm run worldplay -- serve worlds/<name> --port <p>` there. `collectBundle` takes `package.json` and `package-lock.json` (both required), `tsconfig*.json`, `worldgen.config.json`, `models.json` and `src/**`, plus every file of the world. It skips `node_modules`, `runs` and `.git` at any depth, and leaves out `test/`. Why: serving needs nothing else. `models.json` is a root config file other units read. Reversible: yes.
- Sandboxes get 2 CPUs and 4 GiB by default (`--cpu 2 --memory 4Gi` on OpenShell, `--cpus 2` on sbx). `size` overrides this. Why: the YOS-86 "Default size" section. sbx gets no memory flag because the issue gives none. Reversible: yes.
- OpenShell `up` runs `sandbox create --name n [--from img] --cpu --memory --upload <hostdir>:/work --no-git-ignore --detach --no-auto-providers`, then deletes the host copy. I checked in OpenShell's clap source that `--upload` conflicts with a trailing command and that `--no-git-ignore` exists. I assume a directory upload puts its contents at `/work`, and that the default policy lets the sandbox write `/work`. The default image is minimal Ubuntu with no Node, so `image` maps to `--from`, and `upWorld`'s `node -v` check fails with a clear message when Node is missing. Reversible: yes.
- sbx mounts the host directory at the same path. The workspace is therefore `<tmpdir>/worldgen-sandboxes/<name>`, derived from the sandbox name so that a `down` in a later process can find it. It is the workdir, and it is removed only after `sbx rm` succeeds. `sbx stop`'s exit code is ignored, so a sandbox that is already stopped still gets removed. `image` is rejected on sbx. Reversible: yes.
- `start` is `sh -c 'nohup <quoted argv> > <log> 2>&1 < /dev/null &'` sent through each backend's own `exec`. Words are single-quoted for POSIX sh. The serve log goes to `/tmp/worldplay.log`. I assume `openshell sandbox exec` passes each argv word through intact, quoting it if it goes through a remote shell. Why: neither CLI has a documented detach flag for exec. Reversible: yes.
- `upWorld` order: `up`, `node -v` (major 22 or higher), `npm ci --no-audit --no-fund` (900 s bound), `start serve`, then a readiness probe (a `node -e` one-liner, run inside the sandbox, that connects to 127.0.0.1:<port> for up to 60 s), then `expose(port)`. If the probe fails, the error carries `tail -n 20` of the serve log. Any failure after `up` calls `down`. If `down` also fails, the error carries both messages. Why: "tearing down on failure", and a URL is returned only when the world answers. Reversible: yes.
- The admin port (port + 1) is never passed to `expose`. A world port above 65534 is rejected before anything is created. The local backends refuse `public: true` (OpenShell forwards and sbx publishes on 127.0.0.1 only), so only a hosted backend can make the world port public. Why: YOS-86 acceptance 3. Reversible: yes.
- Sandbox names must match `[a-z0-9][a-z0-9-]{0,62}`. Why: they become argv words and host directory names, so the check blocks path traversal through `dirWorkspace`. Reversible: yes.
