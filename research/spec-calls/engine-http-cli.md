# Spec calls: engine-http-cli

- `serve(world, { port, adminPort?, host? })` in #engine creates a fresh runtime and hands it to `listen()` in http.ts, which only turns HTTP into `Runtime` calls. Why: http.ts is a shell file that calls Runtime only, and index.ts owns the vm host. Reversible: yes.
- With `port: 0` and no `adminPort`, both ports are ephemeral; otherwise the admin port defaults to `port + 1` (A-31), and a default past 65535 is a RangeError asking for `adminPort`. Why: `0 + 1` would bind port 1; tests need two free ports. Reversible: yes.
- Both ports bind 127.0.0.1 unless `host`/`--host` says otherwise. Why: a world is a local test fixture; binding every interface is a choice the operator makes. Reversible: yes.
- `/_world/*` on the world port answers 404 `route.not_found` with the same message as any unknown route, before routing, so a world route under `/_world` is never served. Why: the agent under test must not learn of, or reach, the admin surface. Reversible: yes.
- Requests that never reach the world (malformed JSON, a body over 1 MiB, a method other than GET/POST/PUT/PATCH/DELETE, `/_world` on the world port) are answered by http.ts in the world's envelope (`body.invalid` 400, `body.too_large` 413, `method.not_allowed` 405, `route.not_found` 404) and are not in the call log. Why: the log records calls the world handled; these never reached it. Reversible: yes.
- http.ts keeps a copy of api.ts's error-template substitution (`$status`, `$code`, `$message`; a string that is exactly `$status` becomes the number), because `errorBody` is not exported and api.ts is outside this unit. Follow-up: export it from api.ts and drop the copy. Reversible: yes.
- The world port passes the raw request target (path plus query string) to `Runtime.call` with an empty `query`, so `handle()` does all decoding and the log shows the path as sent. An empty body is `undefined`; any other body must be JSON. Reversible: yes.
- Admin routes use the engine's own envelope `{ error: { code, message } }` whatever the world's template. Why: the admin port is the engine's API, and one harness talks to many worlds. Reversible: yes.
- Admin responses: `GET /_world/state` is `Runtime.dump()`; `POST /_world/reset` is `{ ok: true, now }`; `GET /_world/log` is `{ calls: CallRecord[] }`; `POST /_world/clock` takes `{"advance": "<duration>"}` and returns `{ now, jobsFired, jobsFailed }`, 400 `clock.invalid` for a missing or bad duration; `POST /_world/grade/<task>` is `{ task, score }`, 404 `task.unknown` naming the known tasks, 500 `grade.failed` when the grader throws. A known admin path with the wrong method is 405; anything else is 404 listing the admin routes. Why: acceptance fixes the routes, not the bodies; objects leave room to add fields. Reversible: yes.
- Admin calls are not recorded in the call log and do not move the clock (except `/_world/clock`). Why: the log is what the agent under test did. Reversible: yes.
- `gradeDump(world: CheckedWorld, task, dump, journal?)` in #engine wraps tasks.ts's gradeDump with the vm host and accepts only a CheckedWorld, like `serve`. Reversible: yes.
- `worldplay serve` defaults to `--port 4000`, prints `world <url>` and `admin <url>` on stdout, prints check warnings on stderr, and exits 0 after SIGINT or SIGTERM closes both ports; a failed listen (such as EADDRINUSE) is `serve: <message>` on stderr and exit 1. Reversible: yes.
- `worldplay verify` prints `<id> <difficulty> solution 1.000 noop 0.000 decoys [<score>, ...] prefix <score>|-` per task in declaration order from `report.verdicts`, with `-` when there is no prefix score (one write). A world that fails check prints its issues and exits 1; a world without tasks prints `no tasks` and exits 0. Reversible: yes.
- `worldplay grade <dir> <task> --state <file>` prints the score as a plain number (`1`, `0.5`) on stdout and gradeDump's caveat as `caveat: ...` on stderr. A grade issue prints as an issue line and exits 1; an unreadable, non-JSON or malformed dump is one `grade: ...` line on stderr and exit 1; missing `<task>` or `--state` is usage, exit 2. Why: a plain number is easy to script. Reversible: yes.
- New commands parse flags with node:util `parseArgs` (strict, so an unknown option is usage, exit 2); `check` keeps its own parsing. Reversible: yes.
