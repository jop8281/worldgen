# Spec calls: wg-no-silent-guessing (YOS-97)

- REPORT.md renders `## Questions asked of the input` right after `## Assumed and why`: one list item per `plan.open_questions` entry, with `Default answer: ...` nested under it. The section is omitted when `open_questions` is absent or empty, and when the run stopped before a plan. It renders on a stopped run too, because the plan exists and its questions were asked. Why: a reader must see what WorldGen would have asked a human and what it answered in their place. Reversible: yes.
- This supersedes the wg-report call "`plan.open_questions` is not rendered". Why: YOS-97 asks for it. wg-report.md is owned by another unit and was not edited. Reversible: yes.
- Multi-line question and answer text is printed verbatim and stays inside its list item (the shared `item()` indents continuation lines). Why: same rule as assumptions. Reversible: yes.
- `PLAN_BRIEF` names `open_questions` and `default_answer`, and still says to record each default as an assumption with decision and why. `stages.test.ts` asserts both names. Why: the schema field alone did not tell the model to fill it. Reversible: yes.
- No `plan` stage and no `STAGES.plan.done` or `plan.no_assumptions` issue were added. Why: the no-silent-guessing guard already exists as `planSchemaFor('description')` in plan.ts, and run.ts `judgePlan` reports it as `schema.invalid` at `plan.assumptions`. A second guard would duplicate it. `worldgen.test.ts` proves a first description plan with no assumptions is rejected, the retry prompt carries the assumptions message and path, and the corrected plan finishes the run with a checked world. plan.test.ts covers the OpenAPI, CSV and refusal exceptions. YOS-97 acceptance was updated to match this architecture. Reversible: yes.
- The guard does not check that `open_questions` and `assumptions` agree: a plan may list a question with no matching assumption. Detecting which choices the input did not state remains outside YOS-97's scope. Reversible: yes.
