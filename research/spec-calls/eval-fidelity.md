# Spec calls: eval-fidelity

- **Name matching.** Call: A reference item matches a world item by name only: lowercase, drop every character that is not a letter or digit, then equal to the item's name or a listed synonym. No stemming, no model. Why: The spec asks for "resembling the real software" as a number, and a rule written in the reference file can be argued with, where a guess cannot. Read the T2 criteria of `research/linear.md` (zero `field.type_mismatch`, no `transitions.stricter_than_real`) from the Fidelity misses section of `summary.md`. Error items measure producibility only, never the returned status. Reversible: Yes.
- **Canonical first, disjoint names.** Call: The canonical name is tried before synonyms in listed order, and the parser rejects normalized names that repeat within a scope (entities, fields of one entity, states of one set). Why: Disjoint names give the guarantee that one world key satisfies at most one item, statically. A stateful claim-once matcher would add hidden state for the same result. Reversible: Yes.
- **Weights and score.** Call: Weights are positive integers and the score is earned over total, rounded to 4 decimals. An entity's item weight covers its existence, its fields carry their own, and a missing entity forfeits all of them as one `entity.missing` miss. Why: Integers keep test values literal. Reversible: Yes.
- **Field types.** Call: A field matches when its engine type is in the reference's `types`, else `field.type_mismatch` and no credit. Every entry must be an engine field type. Why: Real fields map to several engine types (a price is `money`, `number` or `int`), and a misspelled type would silently never match. Reversible: Yes.
- **State sets and enums.** Call: A state set is satisfied by a `state` field or an `enum` field. An enum counts for the states and is never stricter, because it has no transitions. Why: An enum is any-to-any, so it cannot be stricter than the real product. Reversible: Yes.
- **State-set alternatives and the Linear repoint.** Call: A state set lists `alternatives` after its primary location, and the first location that resolves to a state or enum field wins. Linear's primary location is `workflow_state.type`, with `issue.status` as the alternative. Why: In Linear the states are values of `WorkflowState.type` and an issue only points at one (`research/linear.md` section 4). A flat world is still faithful in spirit. Reversible: Yes.
- **Transitions.** Call: The transitions item is all or nothing. It earns its weight when the world allows every move the real product allows between matched states (`anyToAny: true` lists every ordered pair, as for Linear, which documents no rules). Otherwise one `transitions.stricter_than_real` miss names the forbidden moves. Why: Moves that touch a missing state are skipped, since `state.missing` already charged them. Reversible: Yes.
- **Transitions withheld below two matched states.** Call: With fewer than two reference states matched, the transitions weight is lost as `state.missing` at `<entity>.<field>.transitions`. Why: With fewer than two states no move can be compared, and an empty comparison would otherwise earn the weight for free. Reversible: Yes.
- **Routes.** Call: Routes match on method and path with `{param}` names ignored, against both `routes` and `actions`, or a listed path synonym. Why: Worlds name path parameters freely. Reversible: Yes.
- **Failure cases.** Call: Failure cases record the real status, but a static score cannot see statuses. An error item earns its weight when the world has what makes the failure producible: the route it points at (with that route's synonyms), or a `state` field for a refused move. A miss reuses `route.missing` or `state.missing` at `error <status>: <case>`. The six miss kinds stay closed. Why: The issue fixes the six kinds. Resolving `via` to the reference's own entries keeps the route synonyms in one place. Reversible: Yes.
- **Structural fidelity independent of validity.** Call: Fidelity is scored on the schema-parsed world, with no `checkWorld` and no task verification, whenever the last phase finished. Why: A world that fails check is often the most informative case to score, and the old path ran full verification per case on every summary (cost grew quadratically and tests flaked). Cost: a world that parses but does not check can score high, so fidelity must be read beside `verify`. Reversible: Yes.
- **Recompute in collect.** Call: Fidelity is recomputed from `world.yaml` and the reference on every summary and is not stored in `case.json`. Why: It costs one YAML load and one zod parse per case, and an edited reference shows on the next summary. Storing it would add a field and a stale-number risk. Reversible: Yes.
- **Exact misses in summary.md.** Call: `summary.md` gets a `## Fidelity misses` section with one line per miss and a `missed <n> of <total>` line per scored case. Why: A bare score cannot be acted on, and the section lets a reader see which real-product items a generated world lacks. Reversible: Yes.
- **Floored cell.** Call: The cell is `Math.floor(1000*earned/total)/1000` printed with 3 decimals plus `(earned/total)`, such as `0.957 (68/71)`. Why: Rounding could show 0.7995 as 0.800 and look like it meets the 0.80 target. Reversible: Yes.
- **Metric, never a gate.** Call: The score is never a judge rule, a stop reason or part of `pass`. The column appears only when at least one case has a reference (`-` for the others), so a suite without references prints the old table. A bad reference fails `--dry-run` and refuses a real run before any model call. Why: Out of scope in YOS-96, and old summaries stay comparable. A reference is an input like suite.yaml, so it is validated like one. Reversible: Yes.
- **Linear is any-to-any.** Call: The Linear reference allows every move between states. Why: Real Linear documents no transition rules (`research/linear.md` section 4). Reversible: Yes.
- **Helpdesk provenance.** Call: The helpdesk reference takes `escalated` and the assign, escalate and resolve actions from `research/helpdesk-expected-behaviour.md`, the hand world's target. Zendesk's own statuses are new, open, pending, hold, solved and closed. So 0.9577 measures fidelity to the hand world's target, not to Zendesk. Why: Stating this keeps the number from being read as a Zendesk benchmark. Three real-product items stay missing from the hand world on purpose (`ticket.type`, state `hold`, `GET /search`) so the score is not trivially 1. Reversible: Yes.
- **Target.** Call: At least 0.80 on each referenced case (`helpdesk-sla`, `retail-tau2-known`, `linear-description`) by stress run 2 (YOS-54). Why: The issue sets 0.80. Reversible: Yes.
