- `worldFormatDoc()` in format.ts (exported from #engine) is the whole file: a one-line blockquote saying it is generated by `npm run docs`, then `formatReference()`. The "Do not edit by hand" line moved out of `formatReference()`, which also feeds stage system prompts. Why: the file needs the warning, a prompt does not. Reversible: yes.
- `worldplay docs` writes `worldFormatDoc()` to `prod/world-format.md` found from the CLI file's own location (so it works from any cwd), or to `--out <file>`, and prints `wrote <absolute path>`. Reversible: yes.
- The staleness test is `test/docs.test.ts` (describe `world-format.md`), as the backlog item says, not `test/worlds.test.ts` as AGENTS.md says. It compares the file to `worldFormatDoc()` and tells the reader to run `npm run docs`. Follow-up: AGENTS.md's invariant row should name test/docs.test.ts. Reversible: yes.
- Each field type shows its `examples.def` as one line of JSON (`Example: {...}`), which is also valid YAML flow style. Why: the examples are already proven valid by test/fields.test.ts. Reversible: yes.
- The issue catalog renders one line per code: severity, owner, expected and hint. Expected and hint are functions of an issue's details, so format.ts keeps one example per code, minted with `issue()`, with `<placeholders>` for text and example numbers for counts and scores (snippet limits come from SNIPPET_LIMITS). The table is typed over every IssueCode, so a new code does not compile until it has an example. Follow-up: the examples would sit better next to each catalog entry in issues.ts. Reversible: yes.
- Issues are listed in catalog order and appear in the reference after WorldEdit, under `## Issues`. Reversible: yes.
