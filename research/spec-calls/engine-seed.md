# Spec calls: engine-seed (YOS-22)

- Call: the seed PRNG is mulberry32 seeded with 32-bit FNV-1a of `"<meta.seed>:<entity>"`; `int(lo, hi)` is `lo + floor(rng() * (hi - lo + 1))` and `pick(xs)` is `xs[floor(rng() * xs.length)]`, all drawn from the same per-entity stream. Why: each entity gets its own stream, so adding rows to one entity never shifts another's values, and the test literals pin the algorithm. Reversible: yes, but it changes every rng-using world's seeded state hash.
- Call: seed order is a topological sort over the ref fields that cannot be null (not nullable, or required), the same edges check()'s `seed.cycle` uses; nullable refs are only a soft preference (among ready entities, one whose nullable refs are already seeded goes first). Self-refs and unknown entities are ignored, ties go to declaration order in `entities`, not key order in `seed`. A cycle of non-null refs is rejected by check() before seeding; seedOrder alone falls back to declaration order for it. Why: Acceptance 1 says ref order, and a cycle broken by a nullable edge must seed the same way whatever the declaration order, so every world check() accepts on cycles also seeds. Reversible: yes.
- Call: each entity's rows are created in one privileged transaction; the first enforcement error becomes `constraint.violation` at `['seed', entity]` with `found` = `row <i>, field <f>: <value>` and rule = `<enforce code> (<expected>)`. Seeding stops at that entity. Why: Acceptance 3; the enforce code keeps the store's own reason visible. Reversible: yes.
- Call: a snippet that throws, returns a non-array, or returns a non-object row is `snippet.runtime_error` at `['seed', entity]`; a ctx misuse (`int(5, 1)`, `pick([])`, `rows('unknown')`) throws and lands there too, with the message as hint. Why: check() is total and never throws. Reversible: yes.
- Call: `ctx.fixtures` is a fresh copy of `world.fixtures` per entity run, so a mutating snippet changes neither the world nor the next entity's view. Why: Acceptance 4 says read-only; freezing would throw in the strict-mode sandbox and fail otherwise valid seeds. Reversible: yes.
- Call: seed rows may set any declared state value with no transition check; an undeclared state fails as `field.type`. Seed rows may also set readonly fields and `created_at`/`updated_at`, but never `id`. Why: Acceptance 6 and mode 'privileged'. Reversible: yes.
- Call: `stats.rows` lists every entity (0 when unseeded) and `stats.states['entity.field']` lists every declared state (0 when absent). Why: lints need to see missing states. Reversible: yes.
- Call: check() wraps the host in a per-run memo keyed by (kind, path, source), so the seed layer reuses the compile layer's result and each snippet compiles once. Why: compile is the costly step and a counting host in check.test.ts pins one compile per snippet. Reversible: yes.
- Call: `timeMath` (`plus`, `minutesBetween`) is exported from store.ts for SeedCtx. Why: no shared TimeMath existed in core; other ctx builders may reuse it. Reversible: yes.
