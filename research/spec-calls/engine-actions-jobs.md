# Spec calls: engine-actions-jobs

One bullet per call: call, why, reversible. To be folded into research/decisions.md by engine-freeze, eval-stress-run-2 or docs-design.

- A body that breaks an action's `input` returns 400 `input.invalid`, and the per-field problems go into `$message` as `<field> expected <expected>, found <found>` joined by `; `, unknown keys first, then declared fields in order. Why: U-4 makes the world's error template the only error shape, and it has no slot for a list; the store's 422 messages use the same form. Reversible: yes (a `$problems` placeholder would need a format change).
- Unknown body keys are refused. Absent optional fields with no default are left out of `ctx.body`; declared defaults (and `now` for datetime) are filled in. Ref inputs are type-checked only; the handler decides whether a missing row is a 404. Why: matches the store's strictness without a second ref policy. Reversible: yes.
- Action query keys are passed to `ctx.query` unvalidated. Why: actions declare no query params. Reversible: yes.
- A handler that throws (a SnippetFault, a malformed result, or `ctx.fail` with a status outside 400/404/409/422) returns 500 `action.failed` with message `Action <id> failed: <message>`. A snippet that cannot compile, or a host that cannot compile it, is the same 500. Store refusals keep their own status and code (422 `state.transition`, 409 `field.unique`, 404 `row.not_found`). Why: acceptance 2 asks for 500 on a throw; enforcement errors already carry the right status. Reversible: yes.
- A handler that returns a status of 400 or more is rolled back like a failure, and its own body is returned unchanged (not wrapped in the envelope). Why: a failed call leaves no partial change and does not move the clock (A-16), whichever way it failed. Reversible: yes.
- `Runtime.advance` returns `{ jobsFired, jobsFailed }`. `jobsFired` lists every firing in order, including failed ones; `jobsFailed` lists `{ job, at, message }` for each firing that rolled back. A failed firing changes nothing and does not stop later firings. Engine time still ends at now + by. Why: acceptance 4 counts firings; a failing job must be visible to whoever drives the clock. Reversible: yes.
- Each firing runs at its own due time: `ctx.now()` and the row stamps are the firing instant, not the advance target. Why: A-17 orders firings by time; stamping them all with the end time would erase that order. Reversible: yes.
- After a committed call, jobs due in (call time, call time + tick] fire, after the call commits. Failed calls fire nothing. Why: acceptance 5, and the tick is engine time passing (A-16). Reversible: yes.
- The origin journal (`Runtime.journal()`) records one entry per committed call or firing that changed rows: `{ origin, source, at, rows }`, where `source` is the route or action id or the job name and each row is `{ entity, id, kind, fields }`, from comparing row objects before and after the transaction (cascades and nullifies included). `fields` are the non-engine fields the transaction wrote: all of them for a created or deleted row, the ones whose value changed for an update. Reads and failed calls add nothing. `reset()` clears it. Why: acceptance 6 and A-28; per-field records let a grader tell which origin wrote each field. A diff of row objects covers every write path without instrumenting the store. Reversible: yes.
- `changesSince(seed, end, journal)` accepts a State or a StateDump and expects the journal to cover exactly seed to end. Each net-changed field goes to the origin of the last journal entry that wrote it, so a row that a call and a job both changed yields one Change per origin (call first), each with only its own fields. A created row's `created` Change has the creator's origin; fields the other origin wrote later come as an `updated` Change. A deleted row has the deleter's origin. A field no entry wrote counts as `call`. A row created and deleted in between, or updated back to its seed values, is no change. `fields` excludes `id`, `created_at` and `updated_at` and keeps row key order. Why: A-28 skips job changes by default so jobs cannot zero a correct solution; tagging a whole row `call` when a call touched it put job-written fields into the call set (review round 1). The decision row wins over the earlier row-level call. Reversible: yes.
- `timeMath` (`plus`, `minutesBetween`) lives in api.ts for now; `minutesBetween(a, b)` is `(b - a)` in minutes, unrounded. Why: clock.ts is outside this unit's files. Follow-up: move it to clock.ts so seed and grader ctx share it. Reversible: yes.
- Compiled handlers and jobs are cached per (host, world, snippet path) in WeakMaps. Why: compiling per call costs a vm Script and a realm; the cache holds nothing once the world is dropped. Reversible: yes.
