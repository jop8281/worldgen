# Spec calls: infra-architecture-test

- **SC-1. A type-only import of `Usage` from `worldgen/llm.ts` is allowed anywhere.** Why: `worldgen/events.ts` already does `import type { Usage } from './llm.ts'` in the type sketch, and `src/` is out of scope for this item. `Usage` is token counts, not a model, so it cannot let a module grade with one (A-35). Any other import of `llm.ts` outside `run.ts` and `cli/*.ts` still fails, including `import type { Model }` and `export type { Usage, Model }`. The allowlist is `LLM_DATA_TYPES` in `test/architecture.test.ts`. Reversible: yes. Move `Usage` to `events.ts` or a model-free module and empty the set.
- **SC-2. Type-only imports count for the SDK, `node:vm`, and Node-module rules.** Why: the rules say where a dependency may live, and `tsconfig.engine-core.json` already rejects Node types in core. A type import of `@anthropic-ai/sdk` outside `llm.ts` couples that module to the SDK. Reversible: yes.
- **SC-3. "Node module" means a `node:` specifier or any name `node:module` `isBuiltin()` accepts, such as `fs` or `timers/promises`.** Why: an unprefixed `vm` or `fs` import would otherwise get past rules 4a and 4b. Reversible: yes.
- **SC-4. Through `#engine` means the specifier is exactly `#engine`.** A relative import of `../engine/index.ts` from worldgen or cli also fails. Why: AGENTS.md says not to route around the boundary with a relative import, and the issue text says "other than through `#engine`". Reversible: yes.
- **SC-5. `src/cli/*.ts` means direct children of `src/cli/` only.** Why: it reads as a one-level glob, and AGENTS.md says cli files hold argument parsing with no logic. Reversible: yes.
- **SC-6. A dynamic `import()` with a non-literal argument is not checked.** Why: it cannot be resolved statically, and part A covers the static and literal forms. Reversible: yes. Part B or a later item can ban non-literal `import()` under `src/`.
