# Spec calls: engine-api-crud

- Undeclared query params return 400 `query.unknown` on every standard op, not only list. A list allows its `limitParam`, `cursorParam`, `q` (only when the route has `search` fields), `sort` (only when the route has `sort` fields) and its declared filters. Why: acceptance 2 asks for strictness on lists, and one rule is easier for the agent under test to learn than two. Reversible: yes.
- `?limit` must be a whole number from 1; above the route's `pageSize` it is capped silently, not refused. Why: acceptance 1 says "caps", and real APIs (Stripe, Zendesk) clamp. Reversible: yes.
- Sort and search use the fixed param names `sort` and `q`; `meta.api` names only the paging params. `?sort=field` ascends, `?sort=-field` descends, one field only, and ties always break by id ascending (also under a descending sort). Why: acceptance 3 names these params; A-30 has no sort or search keys. Reversible: yes.
- Cursors are base64url of `encodeURIComponent(JSON.stringify([sort, value, id]))`, encoded by hand because engine core has no Buffer, btoa or TextEncoder. A cursor resumes strictly after (value, id) in the list's order, so deleting the row it names does not skip or repeat rows. A cursor issued under one `sort` is refused (400 `cursor.invalid`) under another. Filters and `q` are not bound into the cursor. Why: matches plan.md "base64 of canonical [sortkey, id]" without Node APIs. Reversible: yes.
- Filters compare with `FIELD_TYPES[t].compare(...) === 0`, not `===`, so equal datetimes written in different ISO forms still match. Route filters and sort may also name the engine fields `id`, `created_at` and `updated_at`. A declared filter or sort name that is neither a field nor an engine field is ignored (so the param is unknown); check.ts should flag it statically (follow-up). Reversible: yes.
- `q` matches when any search field's value, as a string, contains `q` after `toLowerCase()` on both sides. An empty `q` matches every row. Why: acceptance 3 asks only for case-insensitive search; `toLowerCase` is locale-independent. Reversible: yes.
- On a list route, a path param that names a field of the entity is an equality filter (parent-scoped routes such as `/customers/{customer}/tickets`). get, update and delete address the row by the `{id}` param, or the last param when there is no `{id}`. Reversible: yes.
- Routing: a path matches when it has the same number of segments and every segment is equal or binds a `{param}`. The match with the most literal segments wins, ties go to declaration order with routes before actions. Empty segments are dropped, so a trailing slash is ignored. Segments are percent-decoded; a malformed one is 400 `path.invalid`. No match is 404 `route.not_found` with routeId null; a path that matches only under other methods is 405 `method.not_allowed` (routeId null) listing them. Reversible: yes.
- A query string inside `req.path` (`/tickets?status=pending`, as the test-helper solutions write it) is parsed (`+` is a space) and merged under `req.query`, which wins on a clash. Why: client scripts call `api(method, path)` with the query in the path. Reversible: yes.
- A request that matches an action returns 501 `action.unavailable` with the action key as routeId and the state unchanged, until engine-actions-jobs implements actions. Reversible: yes (engine-actions-jobs replaces it).
- Status codes: list 200, get 200, create 201 with the row, update (PATCH or PUT, both merge) 200 with the row, delete 204 with body `null`. A missing or null body on create or update is `{}`; any other non-object body is 400 `body.invalid`. Store errors (404, 409, 422) pass through with their code and message. Reversible: yes.
- Error template substitution walks the whole `meta.api.error` JSON. A string that is exactly `"$status"` becomes the number; otherwise `$status`, `$code` and `$message` are replaced inside strings in one pass, so a message that itself contains `$code` or `$&` is inserted literally. No `$field` or `$param` variable yet: U-4's Stripe `param` needs one (follow-up for the format owner). Reversible: yes.
- `handle` never moves `state.now`; the per-call tick belongs to the runtime (engine-runtime). A read and a failed call return the input `state` object itself. Reversible: yes.
