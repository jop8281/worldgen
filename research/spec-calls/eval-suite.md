- Call: suite.yaml is `{ name, cases }`. Each case is a strict `{ id, input, change?, expect?, note? }`, and `name` names the run directory `<YYYY-MM-DD>-<name>`. Why: the README's `<suite>` segment needs a value, and with strict keys a typo such as `chnage` fails instead of silently dropping the change. Reversible: yes.
- Call: `expect: done | stopped` (default `done`) marks the impossible prompt. A `stopped` case passes on any stop except `model_error`, and a `done` case passes when it ends done and verify passes. Why: the backlog counts an honest stop on an impossible prompt as a pass, and an infrastructure failure is not an honest stop. Reversible: yes.
- Call: input paths in suite.yaml resolve against the suite file's directory (`inputs/stripe.openapi.yaml`), not the repo root or the cwd. Why: a path inside a file is relative to that file, and the suite then works from any cwd and through `--suite`. Reversible: yes.
- Call: the run layout is `<case>/world/` (the world dir), `<case>/events.jsonl`, `<case>/change/events.jsonl` and `<case>/case.json`. The world gets its own subdirectory. Why: createEmitter writes `events.jsonl` into the directory it is given, and runWorldGen may refuse or replace a non-empty outDir. Logs outside the world dir cannot collide with it. Reversible: yes.
- Call: the scorecard reads events.jsonl back from disk with a lenient zod schema, not the in-memory RunResult. `RUN_EVENTS_PARSE` is a compile-time guard that every RunEvent the scorecard reads satisfies that schema. Why: the 'unlogged' flag must reflect what was actually logged, and a broken line must become a reported problem instead of a crash. Reversible: yes.
- Call: 'unlogged' means a step appeared (step_started, step_finished or attempt) with no attempt event, an attempt lacked `ms` or `costUsd`, a line was broken or untyped, or the run returned without `run_finished`. When runWorldGen threw, the missing `run_finished` is reported as a crash, not as unlogged. Why: the AGENTS.md invariant says every attempt's time and cost is logged, and a crash already has its own row status. Reversible: yes.
- Call: case.json records what runWorldGen returned (or threw) for each phase. summary.md is rebuilt after every case from all case.json files in the run dir, in suite order. Why: the stress run reruns cases with `--only` and wants them in the same summary, and a long run shows progress as it goes. Reversible: yes.
- Call: rerunning a case deletes its case directory first. Why: createEmitter appends, so a stale events.jsonl would mix two runs' attempts. Reversible: yes.
- Call: verify is in-process: loadWorld, then checkWorld (its tasks layer runs verifyTask per task), recorded as `pass (N tasks)` or `fail: <codes>`. Why: #engine exports no standalone verify yet, and checkWorld is the same gate worldplay verify uses. The decoy and prefix checks from verify-full arrive through checkWorld with no change here. Reversible: yes, switch to a public verify once #engine exports one.
- Call: `--backend boat` and `--parallel > 1` are parsed and validated, then refused with exit 2 ("boat fan-out lands with sandbox backends"). Local runs are sequential. Why: the backlog requires sequential runs, and the flags reserve the interface for the boat unit. Reversible: yes.
- Call: `--transport claude-cli|sdk`. The default `claude-cli` uses a local placeholder that throws "claude-cli transport not available" until llm.ts exports claudeCliModel. `sdk` builds anthropicModel with `LLM_KEY` from the environment. Why: U-11 makes the CLI transport the default and the SDK opt-in only. Nothing reads .env. Reversible: yes.
- Call: `--dry-run` checks that each input file exists and runs digestInput (no model) on every selected case. It exits 1 if any case is not ready and creates no directories. Why: "validates the suite and input files" should catch an input that will not digest before money is spent. Reversible: yes.
- Call: the suite does not copy research/rehearsal-prompts.md. Why: that file says its prompts avoid the suite's domains so that they stay unseen, and copying them in would contaminate them. `--suite` runs them from a second suite file. Reversible: yes.
- Call: added `retail-tau2-known`, a description case modelled on the tau2-bench retail domain, with a note marking it "known, not held out". The gold-action replay and pass^k are not built. Why: the backlog lists it as a should-have fidelity yardstick, and the replay needs the run loop and a runtime driver from other units. Reversible: yes.
- Call: stripe-partial-refunds narrows to `/v1/charges` and `/v1/refunds`, while stripe-refunds keeps only `/v1/refunds`. Why: a partial refund is bounded by its charge's amount, so the change needs charges in the world. Reversible: yes.
- Call: the run directory date is the UTC date, from `new Date().toISOString()` in the CLI. Why: it is stable across machines, and the CLI is not engine core, so it may read the clock. Reversible: yes.
