# Spec calls: engine-ctx-contract

- Call: the `sig` notation is translated to TS by fixed rules in `code/test/ctx.test.ts`: `name(params) => ret; ...` is an object of methods (no `=> ret` means void), `(params) => ret` is a function, anything else is a TS type as written; an object-shape param becomes a positional param of that type; a string example param (`"15m"`) is `string`; untyped params and shorthand shape fields are `any`; vocabulary aliases `entity = string`, `iso = Iso`, `x = any`. Why: the sigs are written for the model, not as TS, and ctx.ts is read-only for this unit; the rules fit every current sig without editing it, and a sig outside the notation fails the test with its member name. Reversible: yes (tighten by giving params types in ctx.ts, or replace the notation with real TS types).
- Call: "matches" means the sig type is assignable to the interface member (as Acceptance 1 states) plus equal parameter counts, top level and per method of object members such as `db` and `time`. Why: TS assignability accepts a function with fewer parameters, so a sig that drops a parameter would otherwise pass. Reversible: yes.
- Call: interface members declared with method syntax (`now(): Iso`, `ReadDb.get`) are compared with TS method bivariance, so the assignment alone catches neither a sig that widens a typed parameter (`status: number` for `ErrorStatus`, which tells the model 500 is valid) nor one that narrows it (`status: 400 | 404`). A separate parameter check covers both: each parameter the sig types (not `any`) must be assignable to the interface parameter and the interface parameter to it, walking object shapes, array elements and nullable types the same way as the return check. Optional parameters compare by value type, so `list(entity, { where? })` matches `q?: { where?: Where }`; a sig that marks a parameter optional when the interface requires it fails, and the reverse is allowed. Untyped parameters stay `any` and are not compared. Why: strict variance on the whole member would fail `list`, whose sig does not mark its shape optional, while a per-parameter check passes every current sig and fails both drifts with the member and parameter name (`handler.fail`: `(status): sig documents number, interface has ErrorStatus`). Reversible: yes.
- Call: failures are named `<kind>.<member>` (for example `seed.rng`), and a sig constant shared by several registries (WRITE_SIG, NOW, TIME) fails once per member that uses it. Why: the name points the reader at the registry entry to fix. Reversible: yes.
- Call: kinds come from the `SnippetKinds` interface and registries from `CTX_BY_KIND`, both read from the ctx.ts source, so a new snippet kind is covered without editing the test beyond its literal member list. Why: one source of truth (A-19). Reversible: yes.
- Call: "matches" also means the sig and the interface agree on member names in every object shape the sig writes out (a method list such as `db`, or a `{ ... }` shape, in a value, parameter, return type or array element). Each property the interface lacks fails with its path (for example `client.api: return.headers: sig documents a member the interface does not have`), and so does each interface property, optional ones included, that the shape leaves out (for example `grader.changes: (opts).includeJobs: sig leaves out a member the interface has`). A type the sig only names, such as `Row`, is not walked for omissions. Why: the assignment is from a declared variable, not a fresh literal, so TS runs no excess-property check, and a documented `ctx.db.count` would otherwise pass and throw at runtime; and a shape that leaves out an optional member is assignable in both directions, so neither the assignment nor the reverse check sees it, while the model never learns the option exists. Reversible: yes.
- Call: "matches" also means the sig promises nothing narrower than the interface delivers. Every return type and every non-callable value is checked in reverse (interface type assignable to sig type), walking return types, array elements, string index signatures and the properties of object shapes the sig writes out. So `get(entity, id) => Row` against `Row | null` fails with `get.return: sig documents Row, interface has Row | null`. Array readonly-ness is not compared, because element types are compared directly. Why: `member = sig` is covariant in returns and values, so on its own it only proves the sig is a subtype and lets a sig hide `null` from the model. Reversible: yes.
- Call: the reverse check finds one real drift in ctx.ts: `seed.fixtures` is documented as `Record<string, Row[]>`, but fixture rows are `Readonly<Record<string, Value>>` with no branded `id`. ctx.ts is out of scope here, so the test pins that exact failure as `KNOWN_DRIFT`, asserted word for word, and leaves it out of the drifted-copy cases. Why: weakening the check to hide the drift would defeat it, and editing ctx.ts belongs to another unit. Reversible: yes (fix the sig in ctx.ts and empty `KNOWN_DRIFT`).
