# Spec calls: infra-architecture-symbols

- **SC-1. A global is a declaration at the top level of a script file or inside `declare global`.** Anything declared in a module, function or block is local, so a parameter, local const, module-level class or import named `Date` never fires. `globalThis` has no declarations in the checker and counts as global unless a local declaration shadows it. Why: the issue asks for TypeChecker resolution, and this covers both lib files and @types/node. Reversible: yes.
- **SC-2. Type positions count.** `let d: Date` in engine core fires, because the type and the value are one global symbol, and engine time is `Instant` or `Iso`. Why: the issue says "references the global symbols". Reversible: yes. Visit value positions only.
- **SC-3. `Math.random` means the `random` member of the global `Math`, however it is reached.** `Math.random()`, `Math['random']`, `const { random } = Math`, `const { random: r } = Math` and `const M = Math; M.random()` all fire. `Math` itself and its other members are allowed. Why: banning `Math` would ban `Math.floor`, and matching the text `Math.random` misses aliases. Reversible: yes.
- **SC-4. Only the exact file `src/engine/clock.ts` may reference `Date`.** A nested `src/engine/**/clock.ts` does not get the exemption. `Math.random`, `globalThis` and `performance` are banned in clock.ts too. Why: AGENTS.md names one module as the clock. Reversible: yes.
- **SC-5. A brand cast is an `as T` or `<T>x` whose target type contains the brand anywhere.** That includes `CheckIssue[]`, `NonEmpty<CheckIssue>`, `{ world: CheckedWorld }`, `() => CheckedWorld`, unions, local aliases and `x as unknown as TaskVerdict`. The brand is found by the computed brand property declared in the owner file's type alias, so an unrelated local type named `CheckIssue` does not fire. `as const` and `satisfies` never fire. Why: a wrapped forged value is as forged as a bare one. Reversible: yes.
- **SC-6. The brand search reads properties and return types only of types declared in project source, up to depth 6.** Library types such as `Array`, zod schemas and `Promise` contribute only their type arguments. Why: walking library members instantiates generic types without end and overflowed the stack on the real tree. Reversible: yes. A brand nested deeper than 6 levels, or only inside a library type's members, is not seen.
- **SC-7. Type predicates (`x is CheckIssue`) and assertion functions (`asserts x is TaskVerdict`) are not checked.** Why: the acceptance names type assertions only. Reversible: yes. A later item can add them to the brand rule.
- **SC-8. An owner file may assert to its own brand only.** `as CheckedWorld` in issues.ts fires. Why: A-29 says each brand has one minter. Reversible: yes.
- **SC-9. The switch rule applies to every `default:` in src, not only switches over closed unions.** The clause passes when its own statements call `assertNever` from `src/lib/never.ts`, resolved through imports, renames and namespace imports. A call inside a nested function or class does not count, and neither does a local function named `assertNever`. An empty `default:` that falls through to a `case` fires. Why: the acceptance says a `default:` clause whose body does not call assertNever. The checker cannot tell whether a switch is over a closed union. Reversible: yes.
- **SC-10. A missing brand alias, brand property or `assertNever` is reported as a violation** (`src/engine/issues.ts missing brand CheckIssue`, `src/lib/never.ts missing assertNever`). Why: otherwise renaming a brand would make the real-tree case pass without checking anything. Reversible: yes.
- **SC-11. Violations are `<file>:<line> <what>`, sorted by file then line.** Why: a line number makes a failure actionable. Real-tree cases assert `[]` only, so edits under src/ never move an expected line. Reversible: yes.
