## Product failures by root cause

| case | stop | root cause |
|---|---|---|
| bookmarks | no_progress at workflow | The plan names `purge_trash` and `expire_public_links` as scheduled jobs (daily and hourly). The workflow step built both as actions, and no frozen plan test calls an action by either name. Attempts 1 and 2 drew the same `action.unexercised` pair, so the run stopped as `no_progress` at 3.9 min for $0.75. |
| stripe-charges | attempts_exhausted at model | Model attempt 1 left the planned route `get_charge` uncovered (`plan.not_covered`), attempt 2 failed `openapi.field_enum`, and attempt 3 was accepted. Workflow then failed the frozen test `create_charge_uncaptured` twice, so the run backtracked to plan. The replanned run reached model again, but `recordBacktrack` resets the attempt count only for the step backtracked to, here plan. Model still held 3 of its 4 attempts, so the first rerun attempt was its 4th. It failed `plan.not_covered` on `get_charge` again, and the run stopped at 2.5 min for $0.56. |

Both causes are generic, not specific to these prompts:
- **A planned job built as an action.** The workflow step needs to see that the plan's rule names a job.
- **Attempts carried into a rerun after a backtrack to an earlier step.** A step that reruns after the replan keeps the attempts it used before the backtrack. Only the backtrack's target gets a fresh budget.
